# DNS Outage and Resolution Failure


## chunk_id
- 11.20

## category
- failure_modes

## type
- failure_mode

## definition
- inability to resolve hostnames due to dns service issues, cache poisoning, misconfiguration, or expired records, breaking connectivity.

## when_to_use
- microservices relying on service discovery via dns
- debugging sudden connection failures across many services
- designing resilient name resolution and caching behavior

## when_not_to_use
- systems using only fixed ip addresses (rare)
- isolated networks with no dynamic service discovery

## decision_signals
- need: microservices relying on service discovery via dns
- need: debugging sudden connection failures across many services
- willing to accept: can create widespread outage even when services are healthy

## advantages
- motivates connection reuse and dns caching with sensible ttl
- improves resilience by planning fallback and multi-resolver strategies

## disadvantages
- can create widespread outage even when services are healthy
- hard to diagnose if symptoms look like random connection failures

## anti_patterns
- using this when systems using only fixed ip addresses (rare)
- using this when isolated networks with no dynamic service discovery
- ignoring the downside that can create widespread outage even when services are healthy

## real_world_examples
- resolver outage causes all outbound http calls to fail
- misconfigured dns record points to wrong load balancer
