# Configuration Drift


## chunk_id
- 11.23

## category
- failure_modes

## type
- failure_mode

## definition
- runtime configuration diverges across environments or instances due to manual changes, inconsistent rollouts, or untracked overrides.

## when_to_use
- diagnosing inconsistent behavior across pods, nodes, or regions
- systems using feature flags, env vars, and runtime config stores
- designing immutable infrastructure and config governance

## when_not_to_use
- single-instance systems with no configuration variability
- fully immutable deployments with no runtime overrides

## decision_signals
- need: diagnosing inconsistent behavior across pods, nodes, or regions
- need: systems using feature flags, env vars, and runtime config stores
- willing to accept: can produce hard-to-debug partial failures and regressions

## advantages
- motivates configuration as code, auditing, and controlled rollout
- reduces heisenbugs caused by inconsistent settings

## disadvantages
- can produce hard-to-debug partial failures and regressions
- increases operational risk when emergency changes are not tracked

## anti_patterns
- using this when single-instance systems with no configuration variability
- using this when fully immutable deployments with no runtime overrides
- ignoring the downside that can produce hard-to-debug partial failures and regressions

## real_world_examples
- one region has a different timeout value causing higher failure rates
- manual firewall rule changes persist and break deploy assumptions
