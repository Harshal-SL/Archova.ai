# Poison Message


## chunk_id
- 11.9

## category
- failure_modes

## type
- failure_mode

## definition
- a malformed or unexpected message that consistently causes consumer processing to fail, blocking progress or creating infinite retries.

## when_to_use
- message queues and event streaming consumers
- designing retry policies and dead-letter queues
- debugging stuck partitions and repeated processing failures

## when_not_to_use
- strictly validated ingestion pipelines where invalid messages cannot enter
- systems without asynchronous messaging

## decision_signals
- need: message queues and event streaming consumers
- need: designing retry policies and dead-letter queues
- willing to accept: can block a whole partition if processing is ordered

## advantages
- encourages dlqs, schema validation, and safe parsing
- improves operability by preventing stuck consumers

## disadvantages
- can block a whole partition if processing is ordered
- can create retry storms and large backlogs

## anti_patterns
- using this when strictly validated ingestion pipelines where invalid messages cannot enter
- using this when systems without asynchronous messaging
- ignoring the downside that can block a whole partition if processing is ordered

## real_world_examples
- consumer crashes on unexpected null field and retries forever
- a message exceeds size limits and fails deserialization repeatedly
