# Stale Cache and Invalidation Failure


## chunk_id
- 11.12

## category
- failure_modes

## type
- failure_mode

## definition
- cached data remains outdated due to missing invalidation, long ttl, or broken refresh, leading to incorrect responses and inconsistent behavior.

## when_to_use
- systems relying on caching for performance
- debugging mismatched reads vs writes and user-reported inconsistencies
- designing cache invalidation and refresh workflows

## when_not_to_use
- systems with no caching layers
- use cases where stale data is explicitly acceptable and communicated

## decision_signals
- need: systems relying on caching for performance
- need: debugging mismatched reads vs writes and user-reported inconsistencies
- willing to accept: can cause subtle correctness bugs and user trust issues

## advantages
- clarifies where to use ttl, versioning, and write-through strategies
- motivates cache observability and safe fallbacks

## disadvantages
- can cause subtle correctness bugs and user trust issues
- invalidation logic can be complex and error-prone

## anti_patterns
- using this when systems with no caching layers
- using this when use cases where stale data is explicitly acceptable and communicated
- ignoring the downside that can cause subtle correctness bugs and user trust issues

## real_world_examples
- price updates not reflected in cache leading to incorrect checkout totals
- permissions cache stale, allowing access longer than intended
