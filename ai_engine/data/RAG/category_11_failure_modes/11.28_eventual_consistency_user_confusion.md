# Eventual Consistency User Confusion


## chunk_id
- 11.28

## category
- failure_modes

## type
- failure_mode

## definition
- a user-facing failure mode where delayed propagation causes interfaces to show contradictory states, reducing trust and increasing support load.

## when_to_use
- designing ux around asynchronous write propagation
- diagnosing complaints about missing or stale updates
- setting expectations for read-your-writes behavior

## when_not_to_use
- strongly consistent systems with immediate global visibility
- internal batch tools where temporary inconsistency is acceptable

## decision_signals
- need: designing ux around asynchronous write propagation
- need: setting expectations for read-your-writes behavior
- willing to accept: additional product and backend complexity for status transparency

## advantages
- surfaces a common reliability issue from the user perspective
- improves alignment between backend semantics and product behavior

## disadvantages
- additional product and backend complexity for status transparency
- can increase support tickets if not explicitly communicated

## anti_patterns
- showing success without indicating async completion state
- hiding retry and reconciliation states from users
- mixing stale and fresh data in one view without markers

## real_world_examples
- payment marked complete while transaction history lags by minutes
- profile update succeeds but old data appears on another device
