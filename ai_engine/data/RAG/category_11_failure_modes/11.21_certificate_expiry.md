# Certificate Expiry


## chunk_id
- 11.21

## category
- failure_modes

## type
- failure_mode

## definition
- tls certificates expire or are rotated incorrectly, causing handshake failures and widespread connectivity loss.

## when_to_use
- systems using tls everywhere (ingress, service-to-service, databases)
- designing certificate rotation automation and monitoring
- debugging sudden tls handshake errors after long uptime

## when_not_to_use
- environments without tls (not recommended)
- isolated dev setups with short-lived local certificates only

## decision_signals
- need: systems using tls everywhere (ingress, service-to-service, databases)
- need: designing certificate rotation automation and monitoring
- willing to accept: failures can be abrupt and global, affecting many services at once

## advantages
- motivates automated rotation, alerting, and safe rollout of trust bundles
- improves operational discipline for security dependencies

## disadvantages
- failures can be abrupt and global, affecting many services at once
- emergency rotation under outage pressure is risky

## anti_patterns
- using this when environments without tls (not recommended)
- using this when isolated dev setups with short-lived local certificates only
- ignoring the downside that failures can be abrupt and global, affecting many services at once

## real_world_examples
- an intermediate certificate expires, breaking clients across regions
- mTLS service mesh rotation fails, causing partial connectivity loss
