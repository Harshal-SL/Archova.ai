# Deployment Regression


## chunk_id
- 11.24

## category
- failure_modes

## type
- failure_mode

## definition
- a new release introduces correctness or performance issues that degrade service, often interacting with real traffic and data in unexpected ways.

## when_to_use
- designing safe rollout strategies and monitoring
- debugging incidents correlated with deploys
- evaluating canary, blue-green, and rollback approaches

## when_not_to_use
- systems with no deploys or with purely static content
- environments where changes are fully validated against production parity (rare)

## decision_signals
- need: designing safe rollout strategies and monitoring
- need: debugging incidents correlated with deploys
- willing to accept: can rapidly impact many users if rollouts are not controlled

## advantages
- motivates progressive delivery and automated rollback
- improves release confidence through measurable guardrails

## disadvantages
- can rapidly impact many users if rollouts are not controlled
- rollbacks can be hard if the release includes schema changes

## anti_patterns
- using this when systems with no deploys or with purely static content
- using this when environments where changes are fully validated against production parity (rare)
- ignoring the downside that can rapidly impact many users if rollouts are not controlled

## real_world_examples
- a code change increases latency, exhausting thread pools under peak
- a schema migration breaks older app versions or background jobs
