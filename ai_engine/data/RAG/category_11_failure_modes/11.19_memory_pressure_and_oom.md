# Memory Pressure and OOM


## chunk_id
- 11.19

## category
- failure_modes

## type
- failure_mode

## definition
- memory usage grows beyond limits, causing excessive gc, swap, throttling, or out-of-memory kills and crash loops.

## when_to_use
- diagnosing latency spikes followed by restarts
- services using large caches, serialization, or unbounded buffers
- planning resource limits and autoscaling policies

## when_not_to_use
- compute-only stateless workloads with strict memory bounds and no buffering
- short-lived batch jobs where memory spikes are expected and isolated

## decision_signals
- need: diagnosing latency spikes followed by restarts
- need: services using large caches, serialization, or unbounded buffers
- willing to accept: can cause sudden instability and cascading retries

## advantages
- motivates bounded queues, streaming processing, and memory profiling
- improves stability by setting correct limits and alerts

## disadvantages
- can cause sudden instability and cascading retries
- can hide as latency until it becomes catastrophic

## anti_patterns
- using this when compute-only stateless workloads with strict memory bounds and no buffering
- using this when short-lived batch jobs where memory spikes are expected and isolated
- ignoring the downside that can cause sudden instability and cascading retries

## real_world_examples
- large payloads cause buffering and heap growth until oom
- caches grow without eviction and exceed container limits
