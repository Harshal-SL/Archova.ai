# Thundering Herd


## chunk_id
- 11.2

## category
- failure_modes

## type
- failure_mode

## definition
- many clients or workers simultaneously request the same resource after a cache miss or recovery event, overwhelming the backend.

## when_to_use
- designing cache expiration and regeneration strategies
- analyzing traffic spikes after deploys, restarts, or failovers
- protecting shared services from synchronized retries

## when_not_to_use
- workloads with uniform keys and no shared hotspots
- systems where caches are not used and load is stable

## decision_signals
- need: designing cache expiration and regeneration strategies
- need: analyzing traffic spikes after deploys, restarts, or failovers
- willing to accept: can create sudden overload and secondary outages

## advantages
- motivates jitter, request coalescing, and stale-while-revalidate
- helps prevent coordinated spikes during recovery

## disadvantages
- can create sudden overload and secondary outages
- can increase tail latency and error rates dramatically

## anti_patterns
- using this when workloads with uniform keys and no shared hotspots
- using this when systems where caches are not used and load is stable
- ignoring the downside that can create sudden overload and secondary outages

## real_world_examples
- popular homepage cache expires and millions of requests hit the database
- many pods restart and simultaneously warm the same cache keys
