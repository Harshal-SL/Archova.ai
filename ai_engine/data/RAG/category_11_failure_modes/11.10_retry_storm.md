# Retry Storm


## chunk_id
- 11.10

## category
- failure_modes

## type
- failure_mode

## definition
- excessive retries triggered by transient errors or timeouts that amplify load and prevent recovery, often causing a self-sustaining outage.

## when_to_use
- systems with client-side retries and multiple dependency hops
- diagnosing recovery that worsens under load
- designing safe retry policies with jitter and caps

## when_not_to_use
- systems without retries or with strictly bounded retry budgets
- offline batch where retries do not affect shared capacity

## decision_signals
- need: systems with client-side retries and multiple dependency hops
- need: diagnosing recovery that worsens under load
- willing to accept: can overwhelm dependencies and increase error rates

## advantages
- motivates exponential backoff, jitter, and retry budgets
- improves recovery behavior under partial outages

## disadvantages
- can overwhelm dependencies and increase error rates
- hides root causes by masking failures with repeated attempts

## anti_patterns
- using this when systems without retries or with strictly bounded retry budgets
- using this when offline batch where retries do not affect shared capacity
- ignoring the downside that can overwhelm dependencies and increase error rates

## real_world_examples
- timeouts to a database trigger retries that double traffic
- region outage causes clients to retry into the same failing endpoint
