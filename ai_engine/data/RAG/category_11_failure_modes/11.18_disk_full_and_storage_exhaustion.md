# Disk Full and Storage Exhaustion


## chunk_id
- 11.18

## category
- failure_modes

## type
- failure_mode

## definition
- running out of disk or storage quota, causing writes to fail, logs to stop, databases to halt, or nodes to become unstable.

## when_to_use
- systems with local disks, persistent volumes, or log-heavy workloads
- designing retention policies and capacity monitoring
- debugging sudden write failures and database crashes

## when_not_to_use
- purely stateless systems with no local persistence
- systems using managed storage with strict quotas and automated scaling (risk still exists)

## decision_signals
- need: systems with local disks, persistent volumes, or log-heavy workloads
- need: designing retention policies and capacity monitoring
- willing to accept: can cause abrupt failure and data loss risk

## advantages
- motivates retention, compaction, and storage quotas by design
- improves reliability through proactive capacity management

## disadvantages
- can cause abrupt failure and data loss risk
- recovery may require manual cleanup under pressure

## anti_patterns
- using this when purely stateless systems with no local persistence
- using this when systems using managed storage with strict quotas and automated scaling (risk still exists)
- ignoring the downside that can cause abrupt failure and data loss risk

## real_world_examples
- log volume grows unexpectedly and fills disks on all nodes
- a database stops accepting writes when volume reaches 100%
