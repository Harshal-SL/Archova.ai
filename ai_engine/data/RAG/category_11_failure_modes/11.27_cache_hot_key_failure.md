# Cache Hot Key Failure


## chunk_id
- 11.27

## category
- failure_modes

## type
- failure_mode

## definition
- a failure mode where a small set of extremely popular keys saturates cache nodes, causing latency spikes, evictions, and backend overload.

## when_to_use
- diagnosing cache node imbalance and p99 latency regressions
- designing protections for celebrity or flash-sale traffic
- planning cache sharding and key-level admission controls

## when_not_to_use
- uniform traffic distributions with no dominant keys
- systems that do not use shared caching layers

## decision_signals
- need: diagnosing cache node imbalance and p99 latency regressions
- need: designing protections for celebrity or flash-sale traffic
- willing to accept: additional complexity in key splitting and request coalescing

## advantages
- drives targeted mitigation for high-impact keys
- reduces cascading backend failures from cache collapse

## disadvantages
- additional complexity in key splitting and request coalescing
- mitigation can reduce cache efficiency if applied broadly

## anti_patterns
- using single key for globally shared mutable objects
- expiring all replicas of a hot key simultaneously
- scaling cache nodes without fixing key distribution

## real_world_examples
- one product page key saturates a cache partition during launch
- auth metadata key thundering herd after rolling restart
