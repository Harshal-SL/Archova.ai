# Dependency Rate Limit and Throttling


## chunk_id
- 11.22

## category
- failure_modes

## type
- failure_mode

## definition
- a downstream service enforces quotas or throttles requests, causing elevated errors, retries, and user-visible degradation.

## when_to_use
- systems integrating external apis with usage limits
- designing client-side throttling and backoff strategies
- debugging bursts that trigger 429s and timeouts

## when_not_to_use
- fully internal systems with no enforced quotas
- workloads where downstream capacity is guaranteed and isolated

## decision_signals
- need: systems integrating external apis with usage limits
- need: designing client-side throttling and backoff strategies
- willing to accept: can cause sudden partial failures and retry storms

## advantages
- encourages rate limiting, queuing, and graceful degradation upstream
- improves cost and stability under peak load

## disadvantages
- can cause sudden partial failures and retry storms
- can create fairness issues between tenants or features

## anti_patterns
- using this when fully internal systems with no enforced quotas
- using this when workloads where downstream capacity is guaranteed and isolated
- ignoring the downside that can cause sudden partial failures and retry storms

## real_world_examples
- payment provider rate limits during peak events
- identity provider throttles token introspection calls
