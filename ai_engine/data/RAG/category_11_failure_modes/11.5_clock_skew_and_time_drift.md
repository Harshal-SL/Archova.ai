# Clock Skew and Time Drift


## chunk_id
- 11.5

## category
- failure_modes

## type
- failure_mode

## definition
- incorrect or divergent system clocks that break ordering, ttl, authentication, and distributed coordination assumptions.

## when_to_use
- systems relying on expiring tokens, ttl caches, and leases
- distributed ordering and event-time processing pipelines
- debugging signature failures and inconsistent expirations

## when_not_to_use
- systems that never use wall-clock time for correctness
- environments with tightly controlled time sources and no drift risk

## decision_signals
- need: systems relying on expiring tokens, ttl caches, and leases
- need: distributed ordering and event-time processing pipelines
- willing to accept: causes subtle, intermittent bugs and hard-to-reproduce incidents

## advantages
- encourages monotonic time usage and tolerant validation windows
- improves robustness of ttl and token expiry logic

## disadvantages
- causes subtle, intermittent bugs and hard-to-reproduce incidents
- can invalidate auth tokens or cause premature data expiration

## anti_patterns
- using this when systems that never use wall-clock time for correctness
- using this when environments with tightly controlled time sources and no drift risk
- ignoring the downside that causes subtle, intermittent bugs and hard-to-reproduce incidents

## real_world_examples
- jwt validation fails because server clock is behind
- leases expire early causing leader churn and availability drops
