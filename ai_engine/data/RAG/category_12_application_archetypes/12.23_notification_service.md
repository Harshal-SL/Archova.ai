# Notification Service

## chunk_id
- 12.23


## category
- application_archetypes

## type
- application_archetype

## definition
- a system that delivers messages to users across channels (email, sms, push, in-app) with templates, preferences, and delivery tracking.

## when_to_use
- sending transactional alerts and product updates
- unifying multiple providers behind one api
- enforcing user preferences, throttling, and retries

## when_not_to_use
- a single-channel low-volume use case
- when notifications are handled entirely by a third-party platform with no customization

## decision_signals
- need: sending transactional alerts and product updates
- need: unifying multiple providers behind one api
- willing to accept: provider failures and rate limits require robust retry and fallback

## advantages
- centralizes templates, preferences, and compliance policies
- decouples producers from channel-specific delivery concerns

## disadvantages
- provider failures and rate limits require robust retry and fallback
- template changes can cause regressions without preview and testing

## anti_patterns
- using this when a single-channel low-volume use case
- use this when notifications are handled entirely by a third-party platform with no customization
- ignoring the downside that provider failures and rate limits require robust retry and fallback

## real_world_examples
- event-driven notifications for order status and password resets
- per-user opt-out rules and quiet hours enforced in the delivery pipeline
