# High Volume Logging Ingestion

## chunk_id
- 12.42


## category
- application_archetypes

## type
- application_archetype

## definition
- an application focused on ingesting large volumes of logs/events, indexing or aggregating them, and supporting query and retention policies.

## when_to_use
- central logging, clickstream capture, and telemetry pipelines
- needing backpressure, sampling, and cost controls
- building alerting from high-cardinality event streams

## when_not_to_use
- low-volume logs that can be stored directly in a database
- systems where querying is unnecessary and raw archiving is enough

## decision_signals
- need: central logging, clickstream capture, and telemetry pipelines
- need: needing backpressure, sampling, and cost controls
- willing to accept: ingestion and indexing can be expensive without sampling

## advantages
- clear separation of ingest, processing, storage, and query tiers
- scales well with partitioning and asynchronous pipelines

## disadvantages
- ingestion and indexing can be expensive without sampling
- high-cardinality fields make storage and query harder

## anti_patterns
- using this when low-volume logs that can be stored directly in a database
- using this when systems where querying is unnecessary and raw archiving is enough
- ignoring the downside that ingestion and indexing can be expensive without sampling

## real_world_examples
- log pipeline with buffering, parsing, and tiered retention
- clickstream ingestion feeding both real-time alerts and batch analytics
