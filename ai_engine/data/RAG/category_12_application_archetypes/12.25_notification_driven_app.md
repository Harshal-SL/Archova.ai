# Notification Driven App

## chunk_id
- 12.25


## category
- application_archetypes

## type
- application_archetype

## definition
- an application where user engagement and workflows rely heavily on timely notifications across multiple channels.

## when_to_use
- transactional alerts, reminders, and workflow nudges
- systems needing user preferences, throttling, and delivery tracking
- decoupling producers from delivery providers

## when_not_to_use
- apps where notifications are rare and can be sent synchronously
- systems without clear opt-in/opt-out requirements

## decision_signals
- need: transactional alerts, reminders, and workflow nudges
- need: systems needing user preferences, throttling, and delivery tracking
- willing to accept: provider failures and retries can cause duplicates without idempotency

## advantages
- improves user experience with timely and consistent communication
- event-driven delivery scales well across channels

## disadvantages
- provider failures and retries can cause duplicates without idempotency
- compliance and preference handling add complexity

## anti_patterns
- using this when apps where notifications are rare and can be sent synchronously
- using this when systems without clear opt-in/opt-out requirements
- ignoring the downside that provider failures and retries can cause duplicates without idempotency

## real_world_examples
- order status updates and appointment reminders
- security alerts for new login and password changes
