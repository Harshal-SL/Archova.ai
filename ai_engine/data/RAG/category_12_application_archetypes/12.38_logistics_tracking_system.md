# Logistics Tracking System

## chunk_id
- 12.38


## category
- application_archetypes

## type
- application_archetype

## definition
- a system that tracks shipments, statuses, scans, and estimated delivery times across carriers and hubs with event-driven updates.

## when_to_use
- modeling state transitions and event sourcing for shipment lifecycle
- integrating multiple carriers with different data formats and slas
- building customer-facing tracking and internal ops dashboards

## when_not_to_use
- simple delivery workflows without multi-hop tracking
- systems that do not require a full event history

## decision_signals
- need: modeling state transitions and event sourcing for shipment lifecycle
- need: integrating multiple carriers with different data formats and slas
- willing to accept: out-of-order events are common and must be reconciled

## advantages
- event-driven model fits scans and status transitions well
- supports replay and audit of shipment history

## disadvantages
- out-of-order events are common and must be reconciled
- integrations and data normalization are ongoing work

## anti_patterns
- using this when simple delivery workflows without multi-hop tracking
- using this when systems that do not require a full event history
- ignoring the downside that out-of-order events are common and must be reconciled

## real_world_examples
- ingesting scan events and projecting current shipment state
- computing etas from event history and carrier performance stats
