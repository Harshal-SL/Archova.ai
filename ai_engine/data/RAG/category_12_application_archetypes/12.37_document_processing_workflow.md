# Document Processing Workflow

## chunk_id
- 12.37


## category
- application_archetypes

## type
- application_archetype

## definition
- an application that ingests documents, extracts or transforms content, and routes items through multi-step workflows with human review.

## when_to_use
- invoice processing, claims intake, and compliance reviews
- needing asynchronous steps like ocr, classification, and enrichment
- tracking status, retries, and exceptions per document

## when_not_to_use
- simple file upload features with no processing pipeline
- fully synchronous transformations that complete within request budgets

## decision_signals
- need: invoice processing, claims intake, and compliance reviews
- need: needing asynchronous steps like ocr, classification, and enrichment
- willing to accept: pipeline retries and partial failures add complexity

## advantages
- clear state machines and idempotent steps improve reliability
- supports scaling compute-heavy stages independently

## disadvantages
- pipeline retries and partial failures add complexity
- human-in-the-loop review requires careful audit and permissions

## anti_patterns
- using this when simple file upload features with no processing pipeline
- using this when fully synchronous transformations that complete within request budgets
- ignoring the downside that pipeline retries and partial failures add complexity

## real_world_examples
- ocr + extraction + validation pipeline with manual exception queue
- enrichment steps that add metadata and route to downstream systems
