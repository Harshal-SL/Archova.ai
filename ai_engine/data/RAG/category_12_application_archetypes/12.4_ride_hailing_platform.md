# Ride Hailing Platform

## chunk_id
- 12.4


## category
- application_archetypes

## type
- application_archetype

## definition
- a real-time marketplace that matches riders and drivers, tracks location, and prices and dispatches trips under low-latency constraints.

## when_to_use
- designing real-time matching and geo routing services
- planning for bursty demand and regional availability
- modeling event-driven state machines for trip lifecycle

## when_not_to_use
- systems without real-time geo updates or matching
- offline scheduling use cases where latency is not critical

## decision_signals
- need: designing real-time matching and geo routing services
- need: planning for bursty demand and regional availability
- willing to accept: high write volume from location updates can create hotspots

## advantages
- well-defined event flows (trip requested, driver assigned, trip started, trip completed)
- benefits from partitioning by region and entity id

## disadvantages
- high write volume from location updates can create hotspots
- complex failure handling for partial updates and out-of-order events

## anti_patterns
- using this when systems without real-time geo updates or matching
- using this when offline scheduling use cases where latency is not critical
- ignoring the downside that high write volume from location updates can create hotspots

## real_world_examples
- driver location streaming with downsampling and geospatial indexing
- surge pricing and dispatch under regional outages
