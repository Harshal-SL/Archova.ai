# Real Time Chat System

## chunk_id
- 12.10


## category
- application_archetypes

## type
- application_archetype

## definition
- a messaging system that supports low-latency delivery, presence, typing indicators, and durable message history across devices.

## when_to_use
- designing websocket or long-poll channels with fan-out
- modeling ordering and delivery semantics per conversation
- supporting offline delivery and sync across devices

## when_not_to_use
- asynchronous notifications that do not require conversational ordering
- systems where delivery latency is not user-visible

## decision_signals
- need: designing websocket or long-poll channels with fan-out
- need: modeling ordering and delivery semantics per conversation
- willing to accept: presence and fan-out can cause high connection and state load

## advantages
- clear partitioning by conversation_id for ordering
- benefits from durable queues and idempotent processing

## disadvantages
- presence and fan-out can cause high connection and state load
- multi-device sync and message edits add complexity

## anti_patterns
- using this when asynchronous notifications that do not require conversational ordering
- using this when systems where delivery latency is not user-visible
- ignoring the downside that presence and fan-out can cause high connection and state load

## real_world_examples
- storing message history with per-thread ordering and read receipts
- delivering messages via a broker with online/offline fan-out
