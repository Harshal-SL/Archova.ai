# IoT Ingestion Platform

## chunk_id
- 12.30


## category
- application_archetypes

## type
- application_archetype

## definition
- a platform that ingests device telemetry at scale, validates and normalizes events, and routes streams to storage and analytics.

## when_to_use
- high-volume telemetry with bursty device connectivity
- multi-tenant device fleets and per-tenant quotas
- building streaming and batch analytics from sensor data

## when_not_to_use
- low-rate device reporting that can be handled with direct api writes
- environments without reliable device identity and provisioning

## decision_signals
- need: high-volume telemetry with bursty device connectivity
- need: multi-tenant device fleets and per-tenant quotas
- willing to accept: device churn and intermittent connectivity complicate pipelines

## advantages
- natural fit for streaming ingestion and partitioning by device_id
- supports multiple sinks (time-series store, lake, alerts)

## disadvantages
- device churn and intermittent connectivity complicate pipelines
- schema evolution and data quality issues are common

## anti_patterns
- using this when low-rate device reporting that can be handled with direct api writes
- using this when environments without reliable device identity and provisioning
- ignoring the downside that device churn and intermittent connectivity complicate pipelines

## real_world_examples
- broker ingestion with topic partitioning and backpressure
- routing critical alerts to real-time consumers and bulk telemetry to data lake
