# Public Developer API

## chunk_id
- 12.16


## category
- application_archetypes

## type
- application_archetype

## definition
- an externally consumed api with authentication, quotas, documentation, and backward compatibility requirements.

## when_to_use
- enabling partners and third-party integrations
- building an ecosystem around your core product
- supporting webhooks and event subscriptions for automation

## when_not_to_use
- internal-only services with no external consumers
- early-stage products where api contracts are still volatile

## decision_signals
- need: enabling partners and third-party integrations
- need: building an ecosystem around your core product
- willing to accept: high support burden for docs, sdk, and compatibility

## advantages
- expands reach through integrations and platform effects
- enforces disciplined api design and operational stability

## disadvantages
- high support burden for docs, sdk, and compatibility
- security and abuse prevention must be first-class

## anti_patterns
- using this when internal-only services with no external consumers
- using this when early-stage products where api contracts are still volatile
- ignoring the downside that high support burden for docs, sdk, and compatibility

## real_world_examples
- payments and billing apis for merchants
- messaging APIs with webhooks and delivery reports
