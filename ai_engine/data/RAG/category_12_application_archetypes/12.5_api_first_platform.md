# API First Platform

## chunk_id
- 12.5


## category
- application_archetypes

## type
- application_archetype

## definition
- a product whose primary interface is a stable, well-documented api used by multiple internal and external clients.

## when_to_use
- enabling partner integrations and developer ecosystems
- supporting multiple frontends (web, mobile, third-party)
- building reusable domain capabilities across teams

## when_not_to_use
- single-purpose apps with one tightly coupled ui
- early prototypes where api stability is not yet required

## decision_signals
- need: enabling partner integrations and developer ecosystems
- need: supporting multiple frontends (web, mobile, third-party)
- willing to accept: breaking changes are expensive and require long deprecation windows

## advantages
- strong contracts enable reuse and independent client evolution
- encourages consistent auth, rate limits, and observability

## disadvantages
- breaking changes are expensive and require long deprecation windows
- documentation and sdk support add ongoing work

## anti_patterns
- using this when single-purpose apps with one tightly coupled ui
- using this when early prototypes where api stability is not yet required
- ignoring the downside that breaking changes are expensive and require long deprecation windows

## real_world_examples
- payments api used by web checkout and partners
- identity api consumed by multiple internal products
