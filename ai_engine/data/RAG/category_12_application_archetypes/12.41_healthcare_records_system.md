# Healthcare Records System

## chunk_id
- 12.41


## category
- application_archetypes

## type
- application_archetype

## definition
- a system that stores and shares clinical records, appointments, and lab results with strict privacy controls, auditing, and interoperability.

## when_to_use
- designing sensitive data systems with strong access controls
- modeling audit trails and least-privilege access for many roles
- integrating with external providers and standards-based data exchange

## when_not_to_use
- applications without regulated data or strict privacy requirements
- systems where external interoperability is not needed

## decision_signals
- need: designing sensitive data systems with strong access controls
- need: modeling audit trails and least-privilege access for many roles
- willing to accept: compliance and interoperability add substantial complexity

## advantages
- strong security and auditing patterns generalize to many regulated domains
- encourages data classification and access monitoring by default

## disadvantages
- compliance and interoperability add substantial complexity
- strict access constraints can complicate performance and caching

## anti_patterns
- using this when applications without regulated data or strict privacy requirements
- using this when systems where external interoperability is not needed
- ignoring the downside that compliance and interoperability add substantial complexity

## real_world_examples
- role-based access with break-glass procedures and full auditing
- data exchange pipelines with validation and normalization
