# Mobile Backend

## chunk_id
- 12.3


## category
- application_archetypes

## type
- application_archetype

## definition
- an api backend for mobile clients emphasizing low latency, efficient payloads, offline tolerance, and secure authentication.

## when_to_use
- native mobile apps needing personalized content and sync
- supporting intermittent connectivity and background retries
- building push notification and deep-link workflows

## when_not_to_use
- purely web applications with no mobile clients
- high-frequency trading or ultra-low-latency systems

## decision_signals
- need: native mobile apps needing personalized content and sync
- need: supporting intermittent connectivity and background retries
- willing to accept: versioning and backward compatibility are challenging

## advantages
- clear client constraints drive good api design and caching
- supports device-specific features (push, biometrics, offline)

## disadvantages
- versioning and backward compatibility are challenging
- offline sync and conflict resolution can be complex

## anti_patterns
- using this when purely web applications with no mobile clients
- using this when high-frequency trading or ultra-low-latency systems
- ignoring the downside that versioning and backward compatibility are challenging

## real_world_examples
- social apps with feed, messaging, and offline drafts
- field service apps syncing work orders and photos
