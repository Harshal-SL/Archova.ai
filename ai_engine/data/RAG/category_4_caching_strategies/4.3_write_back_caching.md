# Write-Back Caching


## chunk_id
- 4.3

## category
- caching_strategies

## type
- caching_strategy

## definition
- a strategy where writes update the cache first and are persisted to the backing store asynchronously later.

## when_to_use
- high write throughput where write latency must be minimized
- aggregations like counters where buffering and batching is acceptable
- systems that can tolerate eventual durability with recovery controls

## when_not_to_use
- compliance-critical data requiring durable writes before ack
- systems without robust flush, retry, and crash recovery design

## decision_signals
- need: high write throughput where write latency must be minimized
- need: aggregations like counters where buffering and batching is acceptable
- willing to accept: risk of data loss on cache failure without durable logging

## advantages
- reduces write latency and can smooth bursts via batching
- increases throughput by decoupling persistence from serving

## disadvantages
- risk of data loss on cache failure without durable logging
- increased complexity for consistency and recovery

## anti_patterns
- using this when compliance-critical data requiring durable writes before ack
- using this when systems without robust flush, retry, and crash recovery design
- ignoring the downside that risk of data loss on cache failure without durable logging

## real_world_examples
- buffering counter increments in cache and flushing periodically
- write-behind caching for derived analytics rollups
