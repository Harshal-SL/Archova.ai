# Event-Driven Cache Invalidation


## chunk_id
- 4.18

## category
- caching_strategies

## type
- caching_strategy

## definition
- invalidating or updating caches using events when data changes, rather than relying solely on ttl expiration.

## when_to_use
- systems with reliable change events and clear entity identifiers
- reducing staleness for frequently updated hot entities
- coordinating invalidation across multiple cache layers

## when_not_to_use
- when events are not reliable or ordering cannot be trusted
- when invalidation fan-out would be too expensive at scale

## decision_signals
- need: systems with reliable change events and clear entity identifiers
- need: reducing staleness for frequently updated hot entities
- willing to accept: adds dependency on messaging reliability and schema evolution

## advantages
- improves freshness while keeping longer ttls and higher hit rates
- enables targeted invalidation and faster convergence after updates

## disadvantages
- adds dependency on messaging reliability and schema evolution
- can create invalidation storms if events are too broad

## anti_patterns
- use this when events are not reliable or ordering cannot be trusted
- use this when invalidation fan-out would be too expensive at scale
- ignoring the downside that adds dependency on messaging reliability and schema evolution

## real_world_examples
- publishing product-updated events to evict cache keys
- updating cache entries in response to user-role-changed events
