# Cache Stampede Prevention


## chunk_id
- 4.8

## category
- caching_strategies

## type
- caching_strategy

## definition
- preventing many concurrent cache misses from triggering duplicate expensive recomputation or database reads.

## when_to_use
- hot keys with synchronized ttl expiration
- cache-aside patterns where origin reads are expensive
- endpoints with high qps and shared objects

## when_not_to_use
- low traffic systems where misses are rare
- when coordination overhead would exceed the benefit

## decision_signals
- need: hot keys with synchronized ttl expiration
- need: cache-aside patterns where origin reads are expensive
- willing to accept: requires coordination like locks or request coalescing

## advantages
- protects the origin from bursts and reduces tail latency
- improves stability during cache rebuilds and cold starts

## disadvantages
- requires coordination like locks or request coalescing
- incorrect locking can reduce throughput or cause deadlocks

## anti_patterns
- using this when low traffic systems where misses are rare
- use this when coordination overhead would exceed the benefit
- ignoring the downside that requires coordination like locks or request coalescing

## real_world_examples
- singleflight request coalescing on cache miss
- adding ttl jitter and soft expiration with background refresh
