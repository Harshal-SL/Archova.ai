# Local In-Memory Cache


## chunk_id
- 4.13

## category
- caching_strategies

## type
- caching_strategy

## definition
- caching data inside a process memory space to minimize latency and reduce remote calls.

## when_to_use
- ultra-low latency lookups and repeated reads within the same instance
- small, frequently accessed reference data
- reducing calls to remote caches for extremely hot keys

## when_not_to_use
- multi-instance deployments requiring consistent shared cache state
- when memory pressure could cause eviction and instability

## decision_signals
- need: ultra-low latency lookups and repeated reads within the same instance
- need: small, frequently accessed reference data
- willing to accept: inconsistent across instances and resets on restart

## advantages
- very low latency and minimal network overhead
- reduces load on distributed caches and databases

## disadvantages
- inconsistent across instances and resets on restart
- can increase memory usage and cause gc pressure

## anti_patterns
- using this when multi-instance deployments requiring consistent shared cache state
- use this when memory pressure could cause eviction and instability
- ignoring the downside that inconsistent across instances and resets on restart

## real_world_examples
- caching feature flag evaluations per instance
- caching schema metadata and configuration with short ttl
