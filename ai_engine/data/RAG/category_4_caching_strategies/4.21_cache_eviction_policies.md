# Cache Eviction Policies


## chunk_id
- 4.21

## category
- caching_strategies

## type
- caching_strategy

## definition
- selecting eviction behavior like lru, lfu, fifo, or ttl-based eviction to control which entries are removed under memory pressure.

## when_to_use
- any bounded cache where memory pressure will occur
- optimizing for hit rate by keeping frequently accessed entries
- preventing large keys from evicting too many small hot entries

## when_not_to_use
- when eviction is unpredictable and correctness depends on the cache
- when the workload is too bursty and eviction churn overwhelms the cache

## decision_signals
- need: any bounded cache where memory pressure will occur
- need: optimizing for hit rate by keeping frequently accessed entries
- willing to accept: eviction behavior can be opaque without good metrics

## advantages
- improves hit rate and stability under memory pressure
- provides predictable tradeoffs between recency and frequency

## disadvantages
- eviction behavior can be opaque without good metrics
- wrong policy can cause churn and poor hit rate

## anti_patterns
- use this when eviction is unpredictable and correctness depends on the cache
- use this when the workload is too bursty and eviction churn overwhelms the cache
- ignoring the downside that eviction behavior can be opaque without good metrics

## real_world_examples
- lru eviction for session-like keys with temporal locality
- lfu eviction for frequently read reference data
