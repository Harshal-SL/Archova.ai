# CDN Caching Strategy


## chunk_id
- 4.22

## category
- caching_strategies

## type
- caching_strategy

## definition
- using a cdn cache to serve static and cacheable dynamic content from edge locations with controlled ttl and invalidation.

## when_to_use
- global audiences and cacheable content like images, scripts, and public pages
- reducing origin load and improving tail latency
- defending origins from traffic spikes and common abuse patterns

## when_not_to_use
- sensitive responses where caching could leak data across users
- dynamic pages with high personalization and no safe variation keys

## decision_signals
- need: global audiences and cacheable content like images, scripts, and public pages
- need: reducing origin load and improving tail latency
- willing to accept: cache debugging can be difficult due to edge behavior

## advantages
- improves global performance and reduces origin costs
- provides built-in caching primitives and edge shielding

## disadvantages
- cache debugging can be difficult due to edge behavior
- invalidation and purges can be slow or costly at large scale

## anti_patterns
- using this when sensitive responses where caching could leak data across users
- using this when dynamic pages with high personalization and no safe variation keys
- ignoring the downside that cache debugging can be difficult due to edge behavior

## real_world_examples
- caching static assets with long ttl and fingerprinted filenames
- caching public api responses with surrogate keys and purge
