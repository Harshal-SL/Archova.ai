# Client-Side Caching


## chunk_id
- 4.23

## category
- caching_strategies

## type
- caching_strategy

## definition
- caching responses in browsers and mobile clients using headers and local storage mechanisms to reduce server requests.

## when_to_use
- static assets and api responses that can be cached per user
- reducing repeated requests for unchanged resources
- improving perceived performance in high-latency networks

## when_not_to_use
- sensitive data that should not persist on client devices
- when clients cannot be trusted to respect cache invalidation rules

## decision_signals
- need: static assets and api responses that can be cached per user
- need: reducing repeated requests for unchanged resources
- willing to accept: can serve stale data without careful cache control

## advantages
- reduces server load and improves client performance
- works well with cdn caching for static resources

## disadvantages
- can serve stale data without careful cache control
- harder to purge quickly compared to server-side caches

## anti_patterns
- using this when sensitive data that should not persist on client devices
- use this when clients cannot be trusted to respect cache invalidation rules
- ignoring the downside that can serve stale data without careful cache control

## real_world_examples
- using etag and cache-control for api responses
- caching static bundles with immutable fingerprints
