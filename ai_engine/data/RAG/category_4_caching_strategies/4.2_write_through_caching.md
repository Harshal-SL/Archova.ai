# Write-Through Caching


## chunk_id
- 4.2

## category
- caching_strategies

## type
- caching_strategy

## definition
- a strategy where writes update the cache and the backing store synchronously so reads see the updated value in cache.

## when_to_use
- read-after-write flows that must hit cache immediately
- systems where cache is part of the primary read path
- simplifying coherence by forcing a single write path

## when_not_to_use
- high write rates where cache writes add unacceptable latency
- when cache availability cannot be made reliable enough for write paths

## decision_signals
- need: read-after-write flows that must hit cache immediately
- need: systems where cache is part of the primary read path
- willing to accept: increases write latency and couples writes to cache health

## advantages
- keeps cache warm and reduces stale cache after writes
- improves read latency by ensuring updated values are cached

## disadvantages
- increases write latency and couples writes to cache health
- can increase write amplification and cache churn

## anti_patterns
- using this when high write rates where cache writes add unacceptable latency
- use this when cache availability cannot be made reliable enough for write paths
- ignoring the downside that increases write latency and couples writes to cache health

## real_world_examples
- updating session state in cache and database during login
- writing inventory updates through a cache layer
