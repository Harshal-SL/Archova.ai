# Distributed Cache


## chunk_id
- 4.14

## category
- caching_strategies

## type
- caching_strategy

## definition
- using a shared cache cluster to serve many application instances with consistent cached data and centralized eviction policies.

## when_to_use
- horizontally scaled services needing shared cached state
- large working sets that do not fit in per-instance memory
- cross-instance session storage and shared computed results

## when_not_to_use
- when the cache becomes a single point of failure without redundancy
- when network latency eliminates most of the caching benefit

## decision_signals
- need: horizontally scaled services needing shared cached state
- need: large working sets that do not fit in per-instance memory
- willing to accept: adds network dependency and operational overhead

## advantages
- improves hit rates across a fleet of instances
- supports centralized management of ttl and eviction

## disadvantages
- adds network dependency and operational overhead
- hotspots can overload cache nodes without partitioning

## anti_patterns
- use this when the cache becomes a single point of failure without redundancy
- use this when network latency eliminates most of the caching benefit
- ignoring the downside that adds network dependency and operational overhead

## real_world_examples
- redis cluster caching user profiles and sessions
- distributed cache for product catalog and pricing snapshots
