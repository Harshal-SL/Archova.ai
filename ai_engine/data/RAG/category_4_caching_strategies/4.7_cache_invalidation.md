# Cache Invalidation


## chunk_id
- 4.7

## category
- caching_strategies

## type
- caching_strategy

## definition
- keeping cached data consistent by expiring, evicting, or updating entries when the source of truth changes.

## when_to_use
- cached data that changes and must remain reasonably fresh
- systems with events or hooks that can trigger invalidation
- preventing stale reads for critical entities

## when_not_to_use
- when invalidation signals are unreliable and would cause widespread staleness
- when the cache stores purely ephemeral or best-effort hints

## decision_signals
- need: cached data that changes and must remain reasonably fresh
- need: systems with events or hooks that can trigger invalidation
- willing to accept: hard to implement correctly for complex relationships

## advantages
- improves freshness without relying only on short ttls
- reduces incorrect behavior caused by stale cache entries

## disadvantages
- hard to implement correctly for complex relationships
- invalidation storms can increase origin load if too broad

## anti_patterns
- use this when invalidation signals are unreliable and would cause widespread staleness
- use this when the cache stores purely ephemeral or best-effort hints
- ignoring the downside that hard to implement correctly for complex relationships

## real_world_examples
- invalidating product cache keys on inventory updates
- evicting user permission cache on role change events
