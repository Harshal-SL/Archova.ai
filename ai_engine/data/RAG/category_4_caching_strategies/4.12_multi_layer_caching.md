# Multi-Layer Caching


## chunk_id
- 4.12

## category
- caching_strategies

## type
- caching_strategy

## definition
- using multiple cache layers like browser, cdn, edge, application, and database caches to reduce latency and origin load.

## when_to_use
- global traffic with cacheable content and repeated reads
- separating concerns like static assets vs personalized responses
- reducing tail latency by serving from the nearest layer

## when_not_to_use
- when caching semantics are unclear and would cause inconsistent behavior
- systems without observability to debug layered cache interactions

## decision_signals
- need: global traffic with cacheable content and repeated reads
- need: separating concerns like static assets vs personalized responses
- willing to accept: invalidation becomes harder across layers

## advantages
- improves latency by serving from the closest cache layer
- reduces load on origins and downstream dependencies

## disadvantages
- invalidation becomes harder across layers
- misaligned ttl and keys can cause confusing staleness

## anti_patterns
- use this when caching semantics are unclear and would cause inconsistent behavior
- using this when systems without observability to debug layered cache interactions
- ignoring the downside that invalidation becomes harder across layers

## real_world_examples
- browser cache for static assets plus cdn cache plus app cache
- edge caching for public content and redis caching for authenticated views
