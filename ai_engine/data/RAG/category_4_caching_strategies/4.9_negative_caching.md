# Negative Caching


## chunk_id
- 4.9

## category
- caching_strategies

## type
- caching_strategy

## definition
- caching known misses or empty results for a short time to prevent repeated expensive lookups.

## when_to_use
- repeated lookups for non-existent keys like usernames or ids
- protecting databases and search systems from brute force scans
- reducing load from repeated 404 or empty responses

## when_not_to_use
- when objects may appear quickly and stale negatives would harm user experience
- when authorization rules could leak existence information

## decision_signals
- need: repeated lookups for non-existent keys like usernames or ids
- need: protecting databases and search systems from brute force scans
- willing to accept: can serve false negatives until expiration

## advantages
- reduces origin load for repeated misses
- improves latency for common not-found paths

## disadvantages
- can serve false negatives until expiration
- requires careful security design to avoid information disclosure

## anti_patterns
- use this when objects may appear quickly and stale negatives would harm user experience
- use this when authorization rules could leak existence information
- ignoring the downside that can serve false negatives until expiration

## real_world_examples
- caching not-found user ids for a short ttl
- caching empty search results for common queries briefly
