# Cache Security and Privacy


## chunk_id
- 4.25

## category
- caching_strategies

## type
- caching_strategy

## definition
- designing caching so sensitive data is protected through key design, access controls, and safe caching boundaries.

## when_to_use
- caching authenticated responses, permissions, or user-specific content
- multi-tenant systems where data isolation is mandatory
- using shared caches and cdn layers that could leak data if misconfigured

## when_not_to_use
- when caching would store secrets, tokens, or pii without encryption and access controls
- when correct cache variation keys cannot be guaranteed

## decision_signals
- need: caching authenticated responses, permissions, or user-specific content
- need: multi-tenant systems where data isolation is mandatory
- willing to accept: adds complexity in key design, encryption, and auditing

## advantages
- reduces risk of data leakage through shared caching layers
- improves compliance posture by enforcing retention and isolation rules

## disadvantages
- adds complexity in key design, encryption, and auditing
- misconfiguration can cause severe security incidents

## anti_patterns
- use this when caching would store secrets, tokens, or pii without encryption and access controls
- use this when correct cache variation keys cannot be guaranteed
- ignoring the downside that adds complexity in key design, encryption, and auditing

## real_world_examples
- disabling cdn caching for authenticated endpoints
- including tenant and user identifiers in cache keys and enforcing ttl limits
