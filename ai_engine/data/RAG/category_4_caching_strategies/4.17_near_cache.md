# Near Cache


## chunk_id
- 4.17

## category
- caching_strategies

## type
- caching_strategy

## definition
- a two-tier caching strategy where a local cache sits in front of a distributed cache to reduce latency for very hot reads.

## when_to_use
- extremely hot keys that dominate traffic
- reducing latency and load on the distributed cache
- services with stable small working sets per instance

## when_not_to_use
- when staleness across instances cannot be tolerated
- when local cache memory pressure would harm service stability

## decision_signals
- need: extremely hot keys that dominate traffic
- need: reducing latency and load on the distributed cache
- willing to accept: increases staleness risk and invalidation complexity

## advantages
- lowers read latency and reduces remote cache calls
- protects distributed cache from hot-key amplification

## disadvantages
- increases staleness risk and invalidation complexity
- adds memory overhead per instance and reduces predictability

## anti_patterns
- use this when staleness across instances cannot be tolerated
- use this when local cache memory pressure would harm service stability
- ignoring the downside that increases staleness risk and invalidation complexity

## real_world_examples
- local in-memory cache for auth tokens backed by redis
- near-cache for feature flags with short ttl
