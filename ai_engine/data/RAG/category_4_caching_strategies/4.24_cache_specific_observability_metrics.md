# Cache Observability Metrics


## chunk_id
- 4.24

## category
- caching_strategies

## type
- caching_strategy

## definition
- measuring cache behavior using hit rate, latency, eviction rate, memory usage, and origin load to guide tuning.

## when_to_use
- operating any production cache that impacts latency or correctness
- tuning ttl, eviction, and stampede prevention mechanisms
- detecting hotspots and cache outages early

## when_not_to_use
- when cache usage is minimal and does not affect user experience
- when metrics would be misinterpreted without baseline and context

## decision_signals
- need: operating any production cache that impacts latency or correctness
- need: tuning ttl, eviction, and stampede prevention mechanisms
- willing to accept: metrics can be misleading without correlating to origin load and slos

## advantages
- enables data-driven cache tuning and capacity planning
- reduces incidents by detecting degradation early

## disadvantages
- metrics can be misleading without correlating to origin load and slos
- requires ongoing dashboard and alert maintenance

## anti_patterns
- use this when cache usage is minimal and does not affect user experience
- use this when metrics would be misinterpreted without baseline and context
- ignoring the downside that metrics can be misleading without correlating to origin load and slos

## real_world_examples
- alerting on rising miss rate and origin qps spikes
- tracking p95 cache latency and eviction churn during peak
