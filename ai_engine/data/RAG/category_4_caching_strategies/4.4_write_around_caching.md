# Write-Around Caching


## chunk_id
- 4.4

## category
- caching_strategies

## type
- caching_strategy

## definition
- a strategy where writes go directly to the backing store and the cache is populated only on reads.

## when_to_use
- write-heavy workloads where caching every write would churn the cache
- data that is rarely read after being written
- reducing cache storage and invalidation complexity

## when_not_to_use
- read-after-write flows that expect cache hits immediately
- workloads where cache misses would overload the database

## decision_signals
- need: write-heavy workloads where caching every write would churn the cache
- need: data that is rarely read after being written
- willing to accept: increased cache misses after writes for hot keys

## advantages
- reduces cache write amplification and churn
- keeps cache focused on hot read data

## disadvantages
- increased cache misses after writes for hot keys
- requires careful ttl and stampede prevention on popular objects

## anti_patterns
- using this when read-after-write flows that expect cache hits immediately
- using this when workloads where cache misses would overload the database
- ignoring the downside that increased cache misses after writes for hot keys

## real_world_examples
- writing event logs to the database and caching only frequently read summaries
- writing user activity records without caching until queried
