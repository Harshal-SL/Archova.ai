# Cache Read/Write Path Optimization


## chunk_id
- 4.26

## category
- caching_strategies

## type
- caching_strategy

## definition
- optimizing read and write flows through cache and origin to reduce tail latency, write amplification, and stale read windows.

## when_to_use
- high-qps services with mixed read and write workloads
- systems suffering p95/p99 latency spikes on cache misses
- workloads where invalidation cost dominates request time

## when_not_to_use
- very small systems where simple cache-aside is sufficient
- systems with strict linearizable reads across all requests

## decision_signals
- need: high-qps services with mixed read and write workloads
- need: systems suffering p95/p99 latency spikes on cache misses
- willing to accept: added complexity in invalidation and consistency controls

## advantages
- lowers tail latency and backend pressure
- improves cache hit quality under mixed traffic

## disadvantages
- added complexity in invalidation and consistency controls
- requires deeper observability of hot keys and churn

## anti_patterns
- optimizing only hit ratio while ignoring miss penalty
- applying write-through globally without key-level profiling
- using one ttl policy for all entities

## real_world_examples
- read coalescing plus stale-while-revalidate for hot catalog keys
- selective write-through for pricing while using cache-aside for profiles
