# Consistent Hashing for Cache Clusters


## chunk_id
- 4.16

## category
- caching_strategies

## type
- caching_strategy

## definition
- distributing cache keys across nodes using consistent hashing so adding or removing nodes moves only a small fraction of keys.

## when_to_use
- sharded cache clusters where rebalancing must be low impact
- scaling cache capacity by adding nodes gradually
- avoiding large cache churn during node replacement

## when_not_to_use
- single-node caches or fully managed caches that handle partitioning internally
- when key distribution is extremely skewed and needs different mitigation

## decision_signals
- need: sharded cache clusters where rebalancing must be low impact
- need: scaling cache capacity by adding nodes gradually
- willing to accept: hotspot keys can still overload specific nodes

## advantages
- reduces cache churn during scaling events
- improves availability by spreading load and keys

## disadvantages
- hotspot keys can still overload specific nodes
- requires careful implementation and observability for rebalancing

## anti_patterns
- using this when single-node caches or fully managed caches that handle partitioning internally
- use this when key distribution is extremely skewed and needs different mitigation
- ignoring the downside that hotspot keys can still overload specific nodes

## real_world_examples
- consistent hashing ring for memcached nodes
- routing cache keys to redis shards via hashing
