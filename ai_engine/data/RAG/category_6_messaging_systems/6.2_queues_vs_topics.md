# Queues Vs Topics

## chunk_id
- 6.2


## category
- messaging_systems

## type
- messaging_pattern

## definition
- choosing between point-to-point queues (one consumer per message) and pub/sub topics (multiple subscribers receive copies of the same event).

## when_to_use
- queues for work distribution where exactly one worker should act per message
- topics for domain events that many consumers can process independently
- event-driven integrations where producers must not know about consumers

## when_not_to_use
- when only one handler should act but you publish to a topic and create duplicate side effects
- when events contain sensitive data that cannot be shared broadly without filtering and authorization
- when the broker cannot support both patterns and you need both semantics

## decision_signals
- need: queues for work distribution where exactly one worker should act per message
- need: topics for domain events that many consumers can process independently
- willing to accept: pub/sub increases eventual consistency and makes tracing across consumers harder

## advantages
- clarifies delivery expectations, scaling model, and consumer isolation
- enables loose coupling by publishing immutable facts to topics

## disadvantages
- pub/sub increases eventual consistency and makes tracing across consumers harder
- migrating between queue and topic semantics can be disruptive

## anti_patterns
- use this when only one handler should act but you publish to a topic and create duplicate side effects
- use this when events contain sensitive data that cannot be shared broadly without filtering and authorization
- ignoring the downside that pub/sub increases eventual consistency and makes tracing across consumers harder

## real_world_examples
- queue for video transcoding jobs processed by competing workers
- topic for order_created events consumed by billing, inventory, and notifications
