# Message Size And Payload Offloading

## chunk_id
- 6.11


## category
- messaging_systems

## type
- messaging_pattern

## definition
- keeping messages small by storing large payloads externally and sending references, to improve throughput and reliability.

## when_to_use
- brokers with strict message size limits
- large attachments (images, documents) tied to async workflows
- reducing network and storage cost for high-volume messaging

## when_not_to_use
- when consumers need the full payload atomically with the message
- when external storage access would add unacceptable latency

## decision_signals
- need: brokers with strict message size limits
- need: large attachments (images, documents) tied to async workflows
- willing to accept: introduces additional dependency on object storage

## advantages
- improves broker performance and reduces storage pressure
- reduces retransmission cost on retries

## disadvantages
- introduces additional dependency on object storage
- requires access control and lifecycle management for payload objects

## anti_patterns
- use this when consumers need the full payload atomically with the message
- use this when external storage access would add unacceptable latency
- ignoring the downside that introduces additional dependency on object storage

## real_world_examples
- storing files in object storage and sending a signed url or object key
- publishing an event with a payload pointer and checksum for integrity
