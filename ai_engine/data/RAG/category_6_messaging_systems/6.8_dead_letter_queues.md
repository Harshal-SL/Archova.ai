# Dead Letter Queues

## chunk_id
- 6.8


## category
- messaging_systems

## type
- messaging_pattern

## definition
- routing messages that cannot be processed successfully to a separate queue for inspection and remediation.

## when_to_use
- isolating poison messages from the main flow
- enabling manual or automated reprocessing workflows
- meeting operational requirements for audit and replay

## when_not_to_use
- when failures are always transient and retries are sufficient
- when dlq handling is not staffed or automated, causing silent buildup

## decision_signals
- need: isolating poison messages from the main flow
- need: enabling manual or automated reprocessing workflows
- willing to accept: adds operational processes for triage and replay

## advantages
- prevents a single bad message from blocking the pipeline
- provides visibility into failure causes and rates

## disadvantages
- adds operational processes for triage and replay
- can mask systemic issues if dlq becomes the default path

## anti_patterns
- use this when failures are always transient and retries are sufficient
- use this when dlq handling is not staffed or automated, causing silent buildup
- ignoring the downside that adds operational processes for triage and replay

## real_world_examples
- moving malformed events to a dlq with error metadata for debugging
- replaying dlq messages after deploying a bug fix
