# Poison Message Handling

## chunk_id
- 6.9


## category
- messaging_systems

## type
- messaging_pattern

## definition
- detecting and isolating messages that repeatedly fail due to data issues, schema mismatch, or non-transient errors.

## when_to_use
- consumer failures that repeat across retries
- schema evolution causing incompatible payloads
- handling unexpected nulls or invalid state transitions

## when_not_to_use
- when failures are clearly transient and recover quickly
- when the correct action is to fail fast and stop intake to protect data

## decision_signals
- need: consumer failures that repeat across retries
- need: schema evolution causing incompatible payloads
- willing to accept: requires triage processes and sometimes manual intervention

## advantages
- keeps pipelines flowing by quarantining bad inputs
- improves reliability by separating remediation from normal processing

## disadvantages
- requires triage processes and sometimes manual intervention
- misclassification can drop messages that should have been retried

## anti_patterns
- use this when failures are clearly transient and recover quickly
- use this when the correct action is to fail fast and stop intake to protect data
- ignoring the downside that requires triage processes and sometimes manual intervention

## real_world_examples
- routing invalid messages to a quarantine topic with validation errors
- pausing a consumer group when poison rate exceeds a threshold
