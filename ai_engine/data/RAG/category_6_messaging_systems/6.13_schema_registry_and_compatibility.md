# Schema Registry And Compatibility

## chunk_id
- 6.13


## category
- messaging_systems

## type
- messaging_pattern

## definition
- a shared service and ruleset for storing schemas and enforcing compatibility across versions for producers and consumers.

## when_to_use
- many producers and consumers share topics at scale
- needing automated checks for backward and forward compatibility
- preventing accidental breaking changes during deployments

## when_not_to_use
- when the messaging domain is small and coordination is easy
- when payloads are unstructured and schema enforcement is not possible

## decision_signals
- need: many producers and consumers share topics at scale
- need: needing automated checks for backward and forward compatibility
- willing to accept: adds operational dependency and governance process

## advantages
- reduces production incidents from incompatible changes
- provides discoverability and tooling for event types

## disadvantages
- adds operational dependency and governance process
- compatibility rules can be misunderstood and misapplied

## anti_patterns
- use this when the messaging domain is small and coordination is easy
- use this when payloads are unstructured and schema enforcement is not possible
- ignoring the downside that adds operational dependency and governance process

## real_world_examples
- rejecting publishes that violate compatibility rules for a topic
- auto-generating client models from approved schemas
