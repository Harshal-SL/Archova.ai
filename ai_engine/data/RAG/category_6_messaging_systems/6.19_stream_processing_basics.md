# Stream Processing Basics

## chunk_id
- 6.19


## category
- messaging_systems

## type
- messaging_pattern

## definition
- continuously transforming and aggregating event streams using windowing, state stores, and exactly-once-like processing guarantees.

## when_to_use
- near-real-time analytics and monitoring
- event-driven enrichment and routing pipelines
- building materialized views from streams

## when_not_to_use
- when batch processing with periodic jobs meets latency requirements
- when stateful processing complexity exceeds team capability

## decision_signals
- need: near-real-time analytics and monitoring
- need: event-driven enrichment and routing pipelines
- willing to accept: state management, reprocessing, and watermarking are complex

## advantages
- enables low-latency insights and reactive automation
- handles unbounded data with incremental computation

## disadvantages
- state management, reprocessing, and watermarking are complex
- correctness depends on ordering, lateness, and dedupe behavior

## anti_patterns
- use this when batch processing with periodic jobs meets latency requirements
- use this when stateful processing complexity exceeds team capability
- ignoring the downside that state management, reprocessing, and watermarking are complex

## real_world_examples
- computing rolling error rate per service from log events
- aggregating clicks into 5-minute windows for dashboards
