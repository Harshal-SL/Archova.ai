# Consumer Groups And Scaling

## chunk_id
- 6.3


## category
- messaging_systems

## type
- messaging_pattern

## definition
- scaling message processing by grouping consumers so each message is processed once per group while allowing parallelism.

## when_to_use
- increasing throughput for a single logical consumer application
- handling partitioned streams with parallel workers
- isolating independent downstream applications by group

## when_not_to_use
- when strict global ordering is required across all messages
- when processing must be single-threaded due to shared state

## decision_signals
- need: increasing throughput for a single logical consumer application
- need: handling partitioned streams with parallel workers
- willing to accept: rebalances can cause temporary pauses and duplicate processing

## advantages
- improves throughput by parallelizing across partitions or queues
- provides a clear isolation boundary between applications

## disadvantages
- rebalances can cause temporary pauses and duplicate processing
- uneven partitions can lead to hot consumers

## anti_patterns
- use this when strict global ordering is required across all messages
- use this when processing must be single-threaded due to shared state
- ignoring the downside that rebalances can cause temporary pauses and duplicate processing

## real_world_examples
- scaling a payments consumer group across 20 worker instances
- running separate consumer groups for analytics and fraud detection
