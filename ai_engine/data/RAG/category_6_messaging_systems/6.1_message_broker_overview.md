# Message Broker Overview

## chunk_id
- 6.1


## category
- messaging_systems

## type
- messaging_pattern

## definition
- an intermediary system that decouples producers and consumers by storing and routing messages via queues or topics.

## when_to_use
- asynchronous workflows where services should not block on each other
- smoothing bursty traffic with buffering
- distributing work across multiple consumer instances

## when_not_to_use
- when strict synchronous request-response is required end-to-end
- when the operational overhead of a broker outweighs the benefit

## decision_signals
- need: asynchronous workflows where services should not block on each other
- need: smoothing bursty traffic with buffering
- willing to accept: introduces new failure modes like backlog growth and retries

## advantages
- decouples services and enables independent scaling
- improves resilience by buffering during partial outages

## disadvantages
- introduces new failure modes like backlog growth and retries
- requires operational expertise for capacity and tuning

## anti_patterns
- use this when strict synchronous request-response is required end-to-end
- use this when the operational overhead of a broker outweighs the benefit
- ignoring the downside that introduces new failure modes like backlog growth and retries

## real_world_examples
- using a broker to process image uploads asynchronously
- publishing order events for downstream inventory and billing services
