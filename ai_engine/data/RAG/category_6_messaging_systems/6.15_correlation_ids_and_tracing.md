# Correlation Ids And Tracing

## chunk_id
- 6.15


## category
- messaging_systems

## type
- messaging_pattern

## definition
- propagating trace and correlation identifiers through messages so distributed flows can be observed end-to-end.

## when_to_use
- debugging async workflows across many services
- enforcing slos and latency budgets for event-driven pipelines
- building audit trails for customer requests

## when_not_to_use
- when messages contain highly sensitive metadata that cannot be propagated
- when tracing systems are absent and ids would not be used

## decision_signals
- need: debugging async workflows across many services
- need: enforcing slos and latency budgets for event-driven pipelines
- willing to accept: adds metadata overhead to messages

## advantages
- improves troubleshooting by linking logs, metrics, and traces
- enables end-to-end latency and error attribution

## disadvantages
- adds metadata overhead to messages
- requires consistent propagation and sampling strategy

## anti_patterns
- use this when messages contain highly sensitive metadata that cannot be propagated
- use this when tracing systems are absent and ids would not be used
- ignoring the downside that adds metadata overhead to messages

## real_world_examples
- adding traceparent headers into message metadata and restoring context in consumers
- using a request_id to correlate api requests with downstream events
