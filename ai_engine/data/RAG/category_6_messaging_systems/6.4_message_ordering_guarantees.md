# Message Ordering Guarantees

## chunk_id
- 6.4


## category
- messaging_systems

## type
- messaging_pattern

## definition
- the rules a messaging system provides for preserving message sequence (per key, per partition, or global ordering).

## when_to_use
- workflows where state transitions must be applied in order
- event streams keyed by entity id (orders, accounts)
- reducing conflict handling in projections

## when_not_to_use
- when ordering requirements are unclear and would reduce throughput
- when enforcing ordering would require a single hot partition

## decision_signals
- need: workflows where state transitions must be applied in order
- need: event streams keyed by entity id (orders, accounts)
- willing to accept: ordering often reduces parallelism and throughput

## advantages
- simplifies consumer logic for state machines
- reduces the need for complex reconciliation

## disadvantages
- ordering often reduces parallelism and throughput
- out-of-order delivery can still happen during retries and failover

## anti_patterns
- use this when ordering requirements are unclear and would reduce throughput
- use this when enforcing ordering would require a single hot partition
- ignoring the downside that ordering often reduces parallelism and throughput

## real_world_examples
- ordering events per order_id so status updates apply correctly
- routing by user_id to keep profile updates in sequence
