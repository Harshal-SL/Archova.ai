# Data Duplication vs Join Decision


## chunk_id
- 2.25

## category
- architecture_decisions

## type
- decision

## definition
- a data modeling decision between duplicating data for fast reads and keeping normalized data requiring joins.

## when_to_use
- duplication for read-optimized views and microservices boundaries
- joins for single-database oltp with strong consistency needs
- duplication when cross-service joins are not feasible

## when_not_to_use
- duplication when data changes frequently and staleness is costly
- joins across services or across regions with high latency

## decision_signals
- need: duplication for read-optimized views and microservices boundaries
- need: joins for single-database oltp with strong consistency needs
- willing to accept: duplication introduces consistency and synchronization overhead

## advantages
- duplication reduces query complexity and improves read latency
- joins preserve a single source of truth and reduce drift

## disadvantages
- duplication introduces consistency and synchronization overhead
- joins can increase latency and create n+1 query risks

## anti_patterns
- using this when duplication when data changes frequently and staleness is costly
- using this when joins across services or across regions with high latency
- ignoring the downside that duplication introduces consistency and synchronization overhead

## real_world_examples
- denormalized product catalog documents for fast browsing
- normalized relational schema for transactions and reporting
