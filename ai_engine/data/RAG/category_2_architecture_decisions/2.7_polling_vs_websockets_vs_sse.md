# Polling vs WebSockets vs SSE


## chunk_id
- 2.7

## category
- architecture_decisions

## type
- decision

## definition
- a realtime delivery choice between periodic polling, persistent bidirectional websockets, and server-sent events (sse).

## when_to_use
- polling for simple periodic updates and broad compatibility
- websockets for low-latency bidirectional messaging
- sse for server-to-client streaming updates

## when_not_to_use
- polling for high-frequency updates or large fanout
- websockets when infrastructure cannot handle many long-lived connections

## decision_signals
- need: polling for simple periodic updates and broad compatibility
- need: websockets for low-latency bidirectional messaging
- willing to accept: long-lived connections require careful scaling and load balancing

## advantages
- websockets support true realtime and interactive ux
- sse is simpler than websockets for one-way streaming

## disadvantages
- long-lived connections require careful scaling and load balancing
- polling increases redundant traffic and server load

## anti_patterns
- using this when polling for high-frequency updates or large fanout
- using this when websockets when infrastructure cannot handle many long-lived connections
- ignoring the downside that long-lived connections require careful scaling and load balancing

## real_world_examples
- chat applications using websockets
- live notifications using sse
