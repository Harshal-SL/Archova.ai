# Synchronous Chain vs Async Chain


## chunk_id
- 2.16

## category
- architecture_decisions

## type
- decision

## definition
- a workflow decision between chaining service calls synchronously and orchestrating work asynchronously via events.

## when_to_use
- synchronous chains for short paths with tight latency budgets
- async chains for long-running workflows and retries
- async chains for cross-domain processes spanning many services

## when_not_to_use
- synchronous chains when fanout creates cascading failures
- async chains when strict immediate consistency is required end-to-end

## decision_signals
- need: synchronous chains for short paths with tight latency budgets
- need: async chains for long-running workflows and retries
- willing to accept: synchronous chains amplify latency and failure propagation

## advantages
- synchronous chains are straightforward and immediate
- async chains improve resilience and decouple services

## disadvantages
- synchronous chains amplify latency and failure propagation
- async chains add observability, ordering, and consistency complexity

## anti_patterns
- using this when synchronous chains when fanout creates cascading failures
- using this when async chains when strict immediate consistency is required end-to-end
- ignoring the downside that synchronous chains amplify latency and failure propagation

## real_world_examples
- synchronous checkout validation calls
- asynchronous order fulfillment via events
