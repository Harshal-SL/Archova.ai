# CDN vs Backend Delivery Decision


## chunk_id
- 2.19

## category
- architecture_decisions

## type
- decision

## definition
- a delivery decision between serving content via edge caching (cdn) or directly from backend origin systems.

## when_to_use
- cdn for static assets and globally distributed users
- backend delivery for personalized and highly dynamic responses
- cdn for large media to reduce origin bandwidth

## when_not_to_use
- cdn for rapidly changing content without cache controls
- backend-only delivery when edge caching would meet slos cheaply

## decision_signals
- need: cdn for static assets and globally distributed users
- need: backend delivery for personalized and highly dynamic responses
- willing to accept: cdn requires cache control and invalidation strategy

## advantages
- cdn reduces latency and offloads origin traffic
- backend delivery simplifies correctness for dynamic content

## disadvantages
- cdn requires cache control and invalidation strategy
- backend delivery increases origin cost and tail latency globally

## anti_patterns
- using this when cdn for rapidly changing content without cache controls
- using this when backend-only delivery when edge caching would meet slos cheaply
- ignoring the downside that cdn requires cache control and invalidation strategy

## real_world_examples
- cdn delivery of images and video segments
- backend delivery of checkout and account pages
