# Sync vs Async Communication


## chunk_id
- 2.3

## category
- architecture_decisions

## type
- decision

## definition
- a communication choice between synchronous request/response and asynchronous messaging with eventual completion.

## when_to_use
- sync calls for simple request flows needing immediate response
- async messaging for decoupling and burst absorption
- async workflows for long-running or failure-prone operations

## when_not_to_use
- sync chains when latency and cascading failures are likely
- async messaging when strict immediate consistency is required

## decision_signals
- need: sync calls for simple request flows needing immediate response
- need: async messaging for decoupling and burst absorption
- willing to accept: sync communication increases coupling and tail latency

## advantages
- sync communication is simple to debug and reason about
- async communication improves resilience and throughput

## disadvantages
- sync communication increases coupling and tail latency
- async communication adds tracing and consistency complexity

## anti_patterns
- using this when sync chains when latency and cascading failures are likely
- using this when async messaging when strict immediate consistency is required
- ignoring the downside that sync communication increases coupling and tail latency

## real_world_examples
- synchronous rest calls for profile reads
- asynchronous order events on kafka
