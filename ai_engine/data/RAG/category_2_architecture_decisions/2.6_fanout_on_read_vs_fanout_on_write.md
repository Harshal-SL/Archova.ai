# Fanout on Read vs Fanout on Write


## chunk_id
- 2.6

## category
- architecture_decisions

## type
- decision

## definition
- a feed and aggregation strategy choosing between composing results at query time (read) or precomputing on writes.

## when_to_use
- fanout on read for fresh data and simpler write paths
- fanout on write for low-latency reads at very high qps
- fanout on write when reads must be predictable and cached

## when_not_to_use
- fanout on write when write amplification is too high
- fanout on read when query-time joins break latency slos

## decision_signals
- need: fanout on read for fresh data and simpler write paths
- need: fanout on write for low-latency reads at very high qps
- willing to accept: fanout on write increases complexity and eventual consistency risk

## advantages
- fanout on write enables fast reads and simple clients
- fanout on read reduces write complexity and storage duplication

## disadvantages
- fanout on write increases complexity and eventual consistency risk
- fanout on read can cause expensive queries and hotspots

## anti_patterns
- using this when fanout on write when write amplification is too high
- using this when fanout on read when query-time joins break latency slos
- ignoring the downside that fanout on write increases complexity and eventual consistency risk

## real_world_examples
- precomputed social feeds for followers (fanout on write)
- dashboard composition at request time (fanout on read)
