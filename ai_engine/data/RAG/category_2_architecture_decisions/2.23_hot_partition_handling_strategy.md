# Hot Partition Handling Strategy


## chunk_id
- 2.23

## category
- architecture_decisions

## type
- decision

## definition
- a strategy set for mitigating key skew where a small set of partitions or shards receive disproportionate traffic.

## when_to_use
- sharded systems with celebrity keys or bursty access patterns
- rate-limited datastores showing throttling on specific partitions
- multi-tenant systems with noisy neighbor hotspots

## when_not_to_use
- uniform workloads without measurable hotspots
- before validating skew via metrics and tracing

## decision_signals
- need: sharded systems with celebrity keys or bursty access patterns
- need: rate-limited datastores showing throttling on specific partitions
- willing to accept: adds complexity in routing, resharding, or key design

## advantages
- improves tail latency and reduces throttling risk
- increases system stability under burst traffic

## disadvantages
- adds complexity in routing, resharding, or key design
- may increase write amplification and operational overhead

## anti_patterns
- using this when uniform workloads without measurable hotspots
- using this when before validating skew via metrics and tracing
- ignoring the downside that adds complexity in routing, resharding, or key design

## real_world_examples
- key salting for hot counters in redis
- partition splitting for hotspot tenants in distributed databases
