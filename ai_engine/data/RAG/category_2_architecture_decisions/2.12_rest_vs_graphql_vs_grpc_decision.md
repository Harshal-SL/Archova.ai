# REST vs GraphQL vs gRPC Decision


## chunk_id
- 2.12

## category
- architecture_decisions

## type
- decision

## definition
- an api protocol decision between rest resources, graphql query graphs, and grpc contract-first rpc.

## when_to_use
- rest for simple resource apis and broad tooling
- graphql for diverse clients needing flexible field selection
- grpc for internal low-latency service-to-service calls

## when_not_to_use
- graphql for simple crud where rest is sufficient
- grpc for public browser clients without compatible gateways

## decision_signals
- need: rest for simple resource apis and broad tooling
- need: graphql for diverse clients needing flexible field selection
- willing to accept: graphql can introduce n+1 queries and complex governance

## advantages
- rest is cache-friendly and easy to operate at scale
- graphql reduces over-fetching and client round trips

## disadvantages
- graphql can introduce n+1 queries and complex governance
- grpc adds tooling and debugging complexity for external clients

## anti_patterns
- using this when graphql for simple crud where rest is sufficient
- using this when grpc for public browser clients without compatible gateways
- ignoring the downside that graphql can introduce n+1 queries and complex governance

## real_world_examples
- github graphql api for flexible clients
- internal microservices using grpc for performance
