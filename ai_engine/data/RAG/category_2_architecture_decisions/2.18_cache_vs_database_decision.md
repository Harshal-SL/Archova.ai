# Cache vs Database Decision


## chunk_id
- 2.18

## category
- architecture_decisions

## type
- decision

## definition
- a performance decision between serving reads from a cache versus relying on database optimization and scaling.

## when_to_use
- caching for hot keys and expensive repeated reads
- database-first for correctness-critical reads and writes
- caching when latency slos require sub-millisecond responses

## when_not_to_use
- caching when stale data causes user-visible correctness issues
- database-only when read load is cheaper to offload to cache

## decision_signals
- need: caching for hot keys and expensive repeated reads
- need: database-first for correctness-critical reads and writes
- willing to accept: cache invalidation is complex and error-prone

## advantages
- caching reduces latency and origin database load
- database remains the single source of truth

## disadvantages
- cache invalidation is complex and error-prone
- caching can hide underlying database design issues

## anti_patterns
- using this when caching when stale data causes user-visible correctness issues
- using this when database-only when read load is cheaper to offload to cache
- ignoring the downside that cache invalidation is complex and error-prone

## real_world_examples
- redis for session and catalog hot reads
- database indexing and read replicas for consistent reads
