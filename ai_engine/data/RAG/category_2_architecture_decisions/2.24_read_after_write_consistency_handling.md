# Read-after-Write Consistency Handling


## chunk_id
- 2.24

## category
- architecture_decisions

## type
- decision

## definition
- a consistency technique ensuring a user or session can immediately read its own recent writes in eventually consistent systems.

## when_to_use
- user settings and profile updates where ux expects immediate visibility
- write-followed-by-read flows behind caches and replicas
- distributed systems using eventual consistency for scale

## when_not_to_use
- when stale reads are acceptable and simpler designs suffice
- when global strong consistency is required for correctness

## decision_signals
- need: user settings and profile updates where ux expects immediate visibility
- need: write-followed-by-read flows behind caches and replicas
- willing to accept: can require sticky routing, cache bypass, or version checks

## advantages
- improves ux by preventing confusing stale reads
- enables eventual consistency while preserving session correctness

## disadvantages
- can require sticky routing, cache bypass, or version checks
- increases complexity in read paths and caching layers

## anti_patterns
- use this when stale reads are acceptable and simpler designs suffice
- use this when global strong consistency is required for correctness
- ignoring the downside that can require sticky routing, cache bypass, or version checks

## real_world_examples
- cache bypass or write-through for recently updated profiles
- leader reads or session tokens for read-your-writes guarantees
