# Authorization (RBAC and ABAC)


## chunk_id
- 9.3

## category
- security_architecture

## type
- security_pattern

## definition
- controlling what an authenticated caller can do using role-based access control (rbac) and attribute-based access control (abac).

## when_to_use
- multi-tenant systems with admin and user roles
- fine-grained permissions over resources and actions
- enforcing policy at gateways and within services

## when_not_to_use
- when requirements are too immature and a simple allowlist is sufficient temporarily
- when policy evaluation latency would break critical hot paths without caching

## decision_signals
- need: multi-tenant systems with admin and user roles
- need: fine-grained permissions over resources and actions
- willing to accept: complex policies are easy to misconfigure and hard to test

## advantages
- provides consistent, auditable access decisions
- scales permission management beyond hard-coded checks

## disadvantages
- complex policies are easy to misconfigure and hard to test
- permission changes can require cache invalidation and propagation

## anti_patterns
- use this when requirements are too immature and a simple allowlist is sufficient temporarily
- use this when policy evaluation latency would break critical hot paths without caching
- ignoring the downside that complex policies are easy to misconfigure and hard to test

## real_world_examples
- rbac for admin actions and abac for tenant and project scoping
- policy checks that verify ownership claims before data access
