# Authentication and Token Validation


## chunk_id
- 9.2

## category
- security_architecture

## type
- security_pattern

## definition
- validating who a caller is using strong authentication and verifying tokens (issuer, audience, expiry, signature) before granting access.

## when_to_use
- apis and services protected by jwt or opaque tokens
- single sign-on across multiple apps and services
- restricting admin and privileged operations

## when_not_to_use
- internal prototypes where identity is out of scope (still avoid exposing externally)
- systems that cannot maintain time sync and key rotation safely

## decision_signals
- need: apis and services protected by jwt or opaque tokens
- need: single sign-on across multiple apps and services
- willing to accept: token validation failures can become widespread outages if misconfigured

## advantages
- prevents unauthorized access through consistent verification rules
- supports centralized identity policies like mfa and conditional access

## disadvantages
- token validation failures can become widespread outages if misconfigured
- clock skew and key rotation can cause intermittent auth errors

## anti_patterns
- using this when internal prototypes where identity is out of scope (still avoid exposing externally)
- using this when systems that cannot maintain time sync and key rotation safely
- ignoring the downside that token validation failures can become widespread outages if misconfigured

## real_world_examples
- validating jwt access tokens at the api gateway with jwks caching
- enforcing short token lifetimes and refresh flows for interactive users
