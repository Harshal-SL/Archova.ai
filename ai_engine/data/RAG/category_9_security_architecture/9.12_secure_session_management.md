# Secure Session Management


## chunk_id
- 9.12

## category
- security_architecture

## type
- security_pattern

## definition
- managing user sessions and cookies securely using short lifetimes, secure attributes, and protection against replay and fixation.

## when_to_use
- browser-based applications with cookies and sessions
- handling refresh tokens or long-lived authentication state
- preventing account takeover through session theft

## when_not_to_use
- stateless token-only apis with no server-side sessions
- systems that cannot rotate session keys or revoke sessions safely

## decision_signals
- need: browser-based applications with cookies and sessions
- need: handling refresh tokens or long-lived authentication state
- willing to accept: stateful sessions add storage and invalidation complexity

## advantages
- reduces risk of session hijacking and fixation
- supports forced logout and revocation flows

## disadvantages
- stateful sessions add storage and invalidation complexity
- misconfigured cookie settings can create severe vulnerabilities

## anti_patterns
- using this when stateless token-only apis with no server-side sessions
- using this when systems that cannot rotate session keys or revoke sessions safely
- ignoring the downside that stateful sessions add storage and invalidation complexity

## real_world_examples
- setting cookies with secure, httpOnly, and sameSite attributes
- rotating session ids after privilege changes and login events
