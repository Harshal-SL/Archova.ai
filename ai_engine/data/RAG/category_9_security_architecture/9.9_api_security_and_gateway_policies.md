# API Security and Gateway Policies


## chunk_id
- 9.9

## category
- security_architecture

## type
- security_pattern

## definition
- protecting apis using centralized enforcement of authentication, authorization, input limits, and security headers at the edge.

## when_to_use
- public apis and mobile backends exposed to the internet
- enforcing consistent policies across many backend services
- reducing direct exposure of internal services

## when_not_to_use
- when policy logic is highly service-specific and would bloat the gateway
- when the gateway is a single point of failure without redundancy

## decision_signals
- need: public apis and mobile backends exposed to the internet
- need: enforcing consistent policies across many backend services
- willing to accept: misconfigurations can block all traffic at once

## advantages
- centralizes enforcement and simplifies clients
- improves observability and audit of incoming requests

## disadvantages
- misconfigurations can block all traffic at once
- adds latency and operational complexity

## anti_patterns
- use this when policy logic is highly service-specific and would bloat the gateway
- use this when the gateway is a single point of failure without redundancy
- ignoring the downside that misconfigurations can block all traffic at once

## real_world_examples
- enforcing jwt validation, request size limits, and allowlisted methods
- applying per-route rate limits and schema validation at the gateway
