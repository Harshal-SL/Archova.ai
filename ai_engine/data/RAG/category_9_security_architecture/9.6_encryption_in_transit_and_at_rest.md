# Encryption in Transit and at Rest


## chunk_id
- 9.6

## category
- security_architecture

## type
- security_pattern

## definition
- protecting data confidentiality and integrity by encrypting network traffic and stored data using managed keys and policies.

## when_to_use
- any system handling sensitive or regulated data
- multi-tenant platforms and shared infrastructure
- protecting backups and logs that may be widely accessible

## when_not_to_use
- when encryption cannot be implemented safely due to key loss risk and no recovery plan
- when performance constraints exist and no tuning or offload is possible

## decision_signals
- need: any system handling sensitive or regulated data
- need: multi-tenant platforms and shared infrastructure
- willing to accept: key management mistakes can cause outages or data loss

## advantages
- reduces data exposure risk during interception or storage compromise
- supports compliance requirements for data protection

## disadvantages
- key management mistakes can cause outages or data loss
- encryption adds operational and troubleshooting complexity

## anti_patterns
- use this when encryption cannot be implemented safely due to key loss risk and no recovery plan
- use this when performance constraints exist and no tuning or offload is possible
- ignoring the downside that key management mistakes can cause outages or data loss

## real_world_examples
- enforcing tls for all service-to-service calls and database connections
- encrypting object storage and backups with customer-managed keys
