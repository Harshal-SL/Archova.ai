# Dependency and Supply Chain Security


## chunk_id
- 9.16

## category
- security_architecture

## type
- security_pattern

## definition
- protecting software supply chains by controlling dependencies, build provenance, and artifact integrity across the delivery pipeline.

## when_to_use
- any system with third-party dependencies and container images
- regulated environments requiring provenance and audit
- reducing risk of compromised packages and build tampering

## when_not_to_use
- when supply chain controls are treated as checkbox compliance without enforcement
- when dependency pinning and updates are not operationally supported

## decision_signals
- need: any system with third-party dependencies and container images
- need: regulated environments requiring provenance and audit
- willing to accept: adds pipeline complexity and governance overhead

## advantages
- reduces risk from compromised dependencies and tooling
- improves traceability from source to running artifact

## disadvantages
- adds pipeline complexity and governance overhead
- strict controls can slow iteration without automation

## anti_patterns
- use this when supply chain controls are treated as checkbox compliance without enforcement
- use this when dependency pinning and updates are not operationally supported
- ignoring the downside that adds pipeline complexity and governance overhead

## real_world_examples
- pinning dependencies, scanning for known vulnerabilities, and generating sboms
- signing build artifacts and verifying signatures at deploy time
