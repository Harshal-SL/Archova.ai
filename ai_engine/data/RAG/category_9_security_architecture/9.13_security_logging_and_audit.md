# Security Logging and Audit


## chunk_id
- 9.13

## category
- security_architecture

## type
- security_pattern

## definition
- recording security-relevant events with sufficient context for detection, forensics, and compliance audits.

## when_to_use
- authentication, authorization, and admin actions
- sensitive data access and configuration changes
- incident response readiness and regulatory requirements

## when_not_to_use
- when logs would include secrets or sensitive payloads without redaction
- when events cannot be protected from tampering or retention is undefined

## decision_signals
- need: authentication, authorization, and admin actions
- need: sensitive data access and configuration changes
- willing to accept: logging can be expensive at high volume without sampling

## advantages
- improves investigation and accountability during incidents
- enables detection of abuse, anomalies, and policy violations

## disadvantages
- logging can be expensive at high volume without sampling
- poor access control to logs can create a secondary data leak

## anti_patterns
- use this when logs would include secrets or sensitive payloads without redaction
- use this when events cannot be protected from tampering or retention is undefined
- ignoring the downside that logging can be expensive at high volume without sampling

## real_world_examples
- auditing role changes and access denials with correlation ids
- alerting on unusual admin actions and failed login spikes
