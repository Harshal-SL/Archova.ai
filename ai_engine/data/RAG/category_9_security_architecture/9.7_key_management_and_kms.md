# Key Management and KMS


## chunk_id
- 9.7

## category
- security_architecture

## type
- security_pattern

## definition
- generating, storing, rotating, and auditing encryption keys using dedicated key management services and controlled access policies.

## when_to_use
- encrypting databases, storage, backups, and application secrets
- implementing envelope encryption with data keys
- meeting audit and compliance requirements for key custody

## when_not_to_use
- when keys would be hard-coded or shared across environments
- when rotation and recovery procedures are not tested and owned

## decision_signals
- need: encrypting databases, storage, backups, and application secrets
- need: implementing envelope encryption with data keys
- willing to accept: misconfiguration can block access to data and cause outages

## advantages
- centralizes key lifecycle management and auditing
- reduces key leakage by avoiding direct key material handling

## disadvantages
- misconfiguration can block access to data and cause outages
- key policy complexity can be hard to reason about

## anti_patterns
- use this when keys would be hard-coded or shared across environments
- use this when rotation and recovery procedures are not tested and owned
- ignoring the downside that misconfiguration can block access to data and cause outages

## real_world_examples
- encrypting data keys with a key encryption key stored in a kms
- rotating keys and rewrapping data keys without re-encrypting all data
