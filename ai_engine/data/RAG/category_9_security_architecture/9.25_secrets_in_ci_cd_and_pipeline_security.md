# Secrets in CI/CD and Pipeline Security


## chunk_id
- 9.25

## category
- security_architecture

## type
- security_pattern

## definition
- securing build and deployment pipelines by isolating credentials, enforcing least privilege, and preventing secret leakage.

## when_to_use
- any automated pipeline with deploy credentials
- reducing risk of compromised runners and build steps
- meeting compliance for separation of duties and audited releases

## when_not_to_use
- when pipelines are fully manual and have no credentials (rare)
- when secrets are already eliminated using short-lived identity and federation

## decision_signals
- need: any automated pipeline with deploy credentials
- need: reducing risk of compromised runners and build steps
- willing to accept: adds complexity to pipeline configuration and tooling

## advantages
- reduces risk of leaked deploy keys and lateral movement
- improves auditability of releases and access to production

## disadvantages
- adds complexity to pipeline configuration and tooling
- misconfiguration can block deployments unexpectedly

## anti_patterns
- use this when pipelines are fully manual and have no credentials (rare)
- use this when secrets are already eliminated using short-lived identity and federation
- ignoring the downside that adds complexity to pipeline configuration and tooling

## real_world_examples
- using short-lived credentials per job and restricting scopes by environment
- scanning logs for secrets and blocking releases when leakage is detected
