# Threat Modeling


## chunk_id
- 9.14

## category
- security_architecture

## type
- security_pattern

## definition
- systematically identifying assets, threats, entry points, and mitigations to reduce security risk before and during implementation.

## when_to_use
- designing new systems or major features
- introducing new data classes like pii or payment data
- changing trust boundaries such as adding external integrations

## when_not_to_use
- when used as a one-time document that is never updated or acted on
- emergency hotfixes where a lightweight review is more appropriate

## decision_signals
- need: designing new systems or major features
- need: introducing new data classes like pii or payment data
- willing to accept: can be time-consuming without a focused scope

## advantages
- finds high-impact risks early when fixes are cheaper
- clarifies trust boundaries and required controls

## disadvantages
- can be time-consuming without a focused scope
- results can be ignored without ownership and follow-up

## anti_patterns
- use this when used as a one-time document that is never updated or acted on
- using this when emergency hotfixes where a lightweight review is more appropriate
- ignoring the downside that can be time-consuming without a focused scope

## real_world_examples
- mapping trust boundaries for an api gateway and internal services
- identifying data exfiltration paths in a multi-tenant platform
