# Connection Pooling

## chunk_id
- 3.6


## category
- scaling_techniques

## type
- scaling_technique

## definition
- reusing a bounded set of network connections to reduce connection setup overhead and protect downstream capacity.

## when_to_use
- high-qps services calling databases or remote apis
- tls-heavy connections where handshakes are expensive
- preventing connection storms during traffic spikes

## when_not_to_use
- when pooling breaks isolation across tenants or credentials
- when long-lived connections are incompatible with the downstream service

## decision_signals
- need: high-qps services calling databases or remote apis
- need: tls-heavy connections where handshakes are expensive
- willing to accept: mis-sized pools can cause queuing and tail latency

## advantages
- reduces latency and cpu from repeated connection setup
- protects databases and services by bounding concurrent connections

## disadvantages
- mis-sized pools can cause queuing and tail latency
- connection leaks can degrade performance over time

## anti_patterns
- use this when pooling breaks isolation across tenants or credentials
- use this when long-lived connections are incompatible with the downstream service
- ignoring the downside that mis-sized pools can cause queuing and tail latency

## real_world_examples
- http client pools for downstream service calls
- database connection pools with per-endpoint limits
