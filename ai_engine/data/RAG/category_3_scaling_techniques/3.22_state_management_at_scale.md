# State Management At Scale

## chunk_id
- 3.22


## category
- scaling_techniques

## type
- scaling_technique

## definition
- scaling stateful systems by choosing appropriate replication, partitioning, and consistency models for data and sessions.

## when_to_use
- stateful services that must scale beyond a single node
- systems needing read-your-writes or strict transaction semantics
- handling sessions, caches, and aggregates across multiple instances

## when_not_to_use
- when state can be removed by redesigning the service as stateless
- when strong consistency requirements are not understood or measured

## decision_signals
- need: stateful services that must scale beyond a single node
- need: systems needing read-your-writes or strict transaction semantics
- willing to accept: adds complexity in data modeling, migrations, and failure handling

## advantages
- enables predictable scaling of core state while preserving correctness
- clarifies tradeoffs between consistency, latency, and availability

## disadvantages
- adds complexity in data modeling, migrations, and failure handling
- incorrect assumptions can cause subtle data corruption or stale reads

## anti_patterns
- use this when state can be removed by redesigning the service as stateless
- use this when strong consistency requirements are not understood or measured
- ignoring the downside that adds complexity in data modeling, migrations, and failure handling

## real_world_examples
- sharding user state while replicating critical reference data
- using idempotency keys to make distributed writes replayable
