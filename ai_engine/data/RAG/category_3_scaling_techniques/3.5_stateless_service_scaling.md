# Stateless Service Scaling

## chunk_id
- 3.5


## category
- scaling_techniques

## type
- scaling_technique

## definition
- designing services so any instance can handle any request without relying on local state.

## when_to_use
- request-response apis needing elastic horizontal scaling
- workloads that benefit from fast replacement and self-healing
- deployments that require rolling updates without draining state

## when_not_to_use
- when latency requires local state but no replication strategy exists
- workloads that require sticky sessions without externalized session state

## decision_signals
- need: request-response apis needing elastic horizontal scaling
- need: workloads that benefit from fast replacement and self-healing
- willing to accept: pushes state to external systems that can become bottlenecks

## advantages
- simplifies scale out, failover, and deployments
- reduces risk of data loss during instance restarts

## disadvantages
- pushes state to external systems that can become bottlenecks
- requires careful design for caching, sessions, and idempotency

## anti_patterns
- use this when latency requires local state but no replication strategy exists
- using this when workloads that require sticky sessions without externalized session state
- ignoring the downside that pushes state to external systems that can become bottlenecks

## real_world_examples
- storing sessions in a distributed cache instead of local memory
- handling retries with idempotency keys rather than in-memory flags
