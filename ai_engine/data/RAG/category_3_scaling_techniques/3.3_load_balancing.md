# Load Balancing

## chunk_id
- 3.3


## category
- scaling_techniques

## type
- scaling_technique

## definition
- distributing traffic across multiple instances to improve throughput, latency, and availability.

## when_to_use
- horizontally scaled services needing even request distribution
- routing around unhealthy instances during failures
- multi-zone or multi-region deployments requiring traffic steering

## when_not_to_use
- single-instance services where routing adds unnecessary complexity
- protocols requiring strict affinity without a plan for failover

## decision_signals
- need: horizontally scaled services needing even request distribution
- need: routing around unhealthy instances during failures
- willing to accept: can mask slow instances without proper observability

## advantages
- improves utilization and reduces hotspot risk
- enables graceful failover and rolling deployments

## disadvantages
- can mask slow instances without proper observability
- requires careful handling of retries and timeouts to avoid amplification

## anti_patterns
- using this when single-instance services where routing adds unnecessary complexity
- using this when protocols requiring strict affinity without a plan for failover
- ignoring the downside that can mask slow instances without proper observability

## real_world_examples
- layer 7 load balancing for http microservices
- distributing worker pulls across multiple queue consumers
