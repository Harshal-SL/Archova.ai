# Async Work Queues

## chunk_id
- 3.7


## category
- scaling_techniques

## type
- scaling_technique

## definition
- decoupling request handling from slow work by enqueuing tasks for background processing.

## when_to_use
- slow or unreliable downstream operations like email, media, and third-party calls
- smoothing bursts and controlling processing rate
- improving perceived latency by returning quickly

## when_not_to_use
- when the user must see immediate results before continuing
- when workflows require strict synchronous transactions across steps

## decision_signals
- need: slow or unreliable downstream operations like email, media, and third-party calls
- need: smoothing bursts and controlling processing rate
- willing to accept: introduces eventual consistency and retry complexity

## advantages
- improves resilience and protects user-facing latency
- enables independent scaling of consumers based on backlog

## disadvantages
- introduces eventual consistency and retry complexity
- requires idempotent processing and good observability

## anti_patterns
- use this when the user must see immediate results before continuing
- use this when workflows require strict synchronous transactions across steps
- ignoring the downside that introduces eventual consistency and retry complexity

## real_world_examples
- checkout enqueues invoice generation and email notifications
- api enqueues video transcoding jobs to worker fleets
