# Request Shedding And Degradation

## chunk_id
- 3.12


## category
- scaling_techniques

## type
- scaling_technique

## definition
- intentionally rejecting or reducing non-critical work under load to preserve critical functionality.

## when_to_use
- protecting core flows during overload or partial outages
- systems with mixed criticality endpoints and background work
- meeting slos by trading completeness for availability

## when_not_to_use
- when every request is equally critical and must be processed
- without a clear prioritization model and user experience plan

## decision_signals
- need: protecting core flows during overload or partial outages
- need: systems with mixed criticality endpoints and background work
- willing to accept: can reduce feature completeness and user satisfaction

## advantages
- prevents cascading failures and protects critical paths
- stabilizes latency and improves overall availability

## disadvantages
- can reduce feature completeness and user satisfaction
- requires careful design to avoid unfairness across users or tenants

## anti_patterns
- use this when every request is equally critical and must be processed
- using this when without a clear prioritization model and user experience plan
- ignoring the downside that can reduce feature completeness and user satisfaction

## real_world_examples
- disabling recommendations while keeping checkout available
- rejecting expensive search filters during peak load
