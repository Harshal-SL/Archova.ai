# Geo Distributed Scaling

## chunk_id
- 3.21


## category
- scaling_techniques

## type
- scaling_technique

## definition
- scaling by distributing compute and traffic across regions and zones to improve latency, availability, and capacity.

## when_to_use
- global user bases requiring low latency
- resilience requirements that include regional disaster recovery
- avoiding single-region capacity constraints and outages

## when_not_to_use
- when a single region meets slos with simpler operations
- systems that cannot tolerate cross-region replication and consistency tradeoffs

## decision_signals
- need: global user bases requiring low latency
- need: resilience requirements that include regional disaster recovery
- willing to accept: increases complexity for data replication, failover, and deployments

## advantages
- reduces latency by serving users closer to the edge
- improves resilience to regional and zonal failures

## disadvantages
- increases complexity for data replication, failover, and deployments
- higher cost due to duplicated infrastructure and cross-region traffic

## anti_patterns
- use this when a single region meets slos with simpler operations
- using this when systems that cannot tolerate cross-region replication and consistency tradeoffs
- ignoring the downside that increases complexity for data replication, failover, and deployments

## real_world_examples
- active-passive failover with warm standby region
- active-active serving with regional routing and health checks
