# Backpressure And Flow Control

## chunk_id
- 3.8


## category
- scaling_techniques

## type
- scaling_technique

## definition
- applying mechanisms that limit intake when processing cannot keep up to prevent overload and cascading failures.

## when_to_use
- streaming and messaging pipelines with variable event rates
- services with bounded resources like thread pools and connection pools
- preventing retry storms and queue buildup

## when_not_to_use
- systems that must accept all input even if it causes downstream collapse
- when backpressure signals cannot propagate to producers meaningfully

## decision_signals
- need: streaming and messaging pipelines with variable event rates
- need: services with bounded resources like thread pools and connection pools
- willing to accept: can reduce throughput if limits are too conservative

## advantages
- stabilizes systems under load and protects critical resources
- improves tail latency by preventing unbounded queues

## disadvantages
- can reduce throughput if limits are too conservative
- requires coordinated signaling and capacity-aware design

## anti_patterns
- using this when systems that must accept all input even if it causes downstream collapse
- use this when backpressure signals cannot propagate to producers meaningfully
- ignoring the downside that can reduce throughput if limits are too conservative

## real_world_examples
- limiting ingestion based on consumer lag and queue depth
- rejecting or deferring requests when thread pools are saturated
