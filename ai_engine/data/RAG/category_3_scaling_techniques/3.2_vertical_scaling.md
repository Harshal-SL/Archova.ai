# Vertical Scaling

## chunk_id
- 3.2


## category
- scaling_techniques

## type
- scaling_technique

## definition
- an implementation technique for scaling up a node by increasing cpu, memory, storage iops, and kernel/runtime limits to raise single-instance capacity.

## when_to_use
- quick capacity increases without re-architecting
- workloads constrained by single-thread performance or memory
- databases and stateful components that are hard to shard initially
- environments where resize operations and maintenance windows are operationally controlled

## when_not_to_use
- when scaling needs will exceed the largest available instance size
- when higher availability requires distributing across failure domains

## decision_signals
- need: quick capacity increases without re-architecting
- need: workloads constrained by single-thread performance or memory
- willing to accept: has hard limits and can be expensive at high tiers

## advantages
- simple to implement with fewer moving parts
- avoids distributed systems complexity for early growth

## disadvantages
- has hard limits and can be expensive at high tiers
- does not automatically improve availability without redundancy

## anti_patterns
- using this when scaling needs will exceed the largest available instance size
- using this when higher availability requires distributing across failure domains
- ignoring the downside that it has hard limits and can be expensive at high tiers

## real_world_examples
- moving a database to a larger instance class
- increasing memory to reduce disk reads and cache misses
