# Cdn And Edge Offload

## chunk_id
- 3.10


## category
- scaling_techniques

## type
- scaling_technique

## definition
- offloading traffic from origins by serving content and selected compute from cdn and edge layers.

## when_to_use
- global traffic patterns with cacheable responses
- protecting origins from bursts and abusive traffic
- reducing latency by serving from edge locations

## when_not_to_use
- highly personalized responses without safe cache partitioning
- workloads requiring dynamic per-request access to centralized state

## decision_signals
- need: global traffic patterns with cacheable responses
- need: protecting origins from bursts and abusive traffic
- willing to accept: cache invalidation and debugging can be difficult

## advantages
- reduces origin load and improves global latency
- provides an additional security and rate limiting layer

## disadvantages
- cache invalidation and debugging can be difficult
- edge behavior can diverge across regions if configuration drifts

## anti_patterns
- using this when highly personalized responses without safe cache partitioning
- using this when workloads requiring dynamic per-request access to centralized state
- ignoring the downside that cache invalidation and debugging can be difficult

## real_world_examples
- caching static assets and api responses with ttl at the cdn
- using edge routing to steer traffic to the nearest healthy region
