# Feature Flags For Safe Scaling Changes

## chunk_id
- 3.20


## category
- scaling_techniques

## type
- scaling_technique

## definition
- controlling rollout of scaling-related changes using flags to limit blast radius and enable fast rollback.

## when_to_use
- changing caching, timeouts, retries, or concurrency limits
- migrating traffic across backends or regions incrementally
- shipping performance optimizations with uncertain impact

## when_not_to_use
- as a permanent substitute for configuration management and cleanup
- when flags cannot be safely evaluated under failure conditions

## decision_signals
- need: changing caching, timeouts, retries, or concurrency limits
- need: migrating traffic across backends or regions incrementally
- willing to accept: adds operational overhead and technical debt if flags linger

## advantages
- reduces risk and enables controlled experimentation
- supports rapid rollback when latency or errors regress

## disadvantages
- adds operational overhead and technical debt if flags linger
- inconsistent flag evaluation can cause hard-to-debug behavior

## anti_patterns
- using this when as a permanent substitute for configuration management and cleanup
- use this when flags cannot be safely evaluated under failure conditions
- ignoring the downside that adds operational overhead and technical debt if flags linger

## real_world_examples
- gradually enabling a new cache layer for 5% of traffic
- switching read routing to replicas behind a kill switch
