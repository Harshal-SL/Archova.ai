# Partitioning And Consistent Hashing

## chunk_id
- 3.15


## category
- scaling_techniques

## type
- scaling_technique

## definition
- dividing workloads and data into partitions using stable keys so traffic and storage distribute evenly across nodes.

## when_to_use
- distributing cache keys, queues, or stream partitions across workers
- scaling stateful systems with per-key locality needs
- reducing contention and hotspots in shared resources

## when_not_to_use
- workloads requiring frequent global aggregation across keys
- when key distribution is unknown and would cause severe skew

## decision_signals
- need: distributing cache keys, queues, or stream partitions across workers
- need: scaling stateful systems with per-key locality needs
- willing to accept: hotspot keys can still dominate a partition

## advantages
- improves scalability by parallelizing work across partitions
- reduces rebalancing impact when adding or removing nodes

## disadvantages
- hotspot keys can still dominate a partition
- changes to partition strategy can require expensive migrations

## anti_patterns
- using this when workloads requiring frequent global aggregation across keys
- use this when key distribution is unknown and would cause severe skew
- ignoring the downside that hotspot keys can still dominate a partition

## real_world_examples
- consistent hashing ring for distributing cache keys across nodes
- partitioning event streams by user id for ordered processing
