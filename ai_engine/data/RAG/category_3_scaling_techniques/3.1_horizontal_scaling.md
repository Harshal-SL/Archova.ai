# Horizontal Scaling

## chunk_id
- 3.1


## category
- scaling_techniques

## type
- scaling_technique

## definition
- scaling by adding more instances of a component to increase throughput and availability.

## when_to_use
- stateless services where requests can be served by any instance
- workloads with parallelizable request handling
- scaling needs that exceed a single machine size

## when_not_to_use
- stateful workloads without a safe partitioning or replication model
- systems limited by a single shared dependency like a primary database

## decision_signals
- need: stateless services where requests can be served by any instance
- need: workloads with parallelizable request handling
- willing to accept: requires load balancing and session handling decisions

## advantages
- scales capacity incrementally with demand
- improves resilience through redundancy

## disadvantages
- requires load balancing and session handling decisions
- can expose shared bottlenecks in data stores and downstream services

## anti_patterns
- using this when stateful workloads without a safe partitioning or replication model
- using this when systems limited by a single shared dependency like a primary database
- ignoring the downside that requires load balancing and session handling decisions

## real_world_examples
- adding more api servers behind a load balancer
- scaling workers by increasing consumer instances
