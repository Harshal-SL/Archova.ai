# Caching For Scale

## chunk_id
- 3.9


## category
- scaling_techniques

## type
- scaling_technique

## definition
- reducing load on expensive systems by storing reusable results closer to the caller.

## when_to_use
- read-heavy endpoints with repeated access to hot keys
- expensive computations that can tolerate bounded staleness
- protecting databases and third-party apis from spikes

## when_not_to_use
- data that cannot be cached safely due to privacy or correctness constraints
- write-heavy workloads where invalidation overhead dominates

## decision_signals
- need: read-heavy endpoints with repeated access to hot keys
- need: expensive computations that can tolerate bounded staleness
- willing to accept: introduces staleness and invalidation complexity

## advantages
- improves latency and increases effective capacity
- reduces downstream load and stabilizes performance

## disadvantages
- introduces staleness and invalidation complexity
- cache stampedes can overload origins if not controlled

## anti_patterns
- using this when data that cannot be cached safely due to privacy or correctness constraints
- using this when write-heavy workloads where invalidation overhead dominates
- ignoring the downside that introduces staleness and invalidation complexity

## real_world_examples
- caching user profiles in a distributed cache with ttl
- caching authorization decisions with short-lived expiration
