# Hot Partition Mitigation

## chunk_id
- 3.16


## category
- scaling_techniques

## type
- scaling_technique

## definition
- reducing hotspots caused by uneven key distribution using techniques like key salting, adaptive partitioning, and targeted caching.

## when_to_use
- sharded databases where a few keys dominate writes or reads
- stream partitions where one partition lags due to skew
- multi-tenant systems where a few tenants create most traffic

## when_not_to_use
- when the root cause is a slow downstream dependency rather than skew
- when salting would break required ordering or query patterns

## decision_signals
- need: sharded databases where a few keys dominate writes or reads
- need: stream partitions where one partition lags due to skew
- willing to accept: can complicate queries and ordering semantics

## advantages
- improves throughput and latency by reducing contention
- increases cluster utilization by balancing work more evenly

## disadvantages
- can complicate queries and ordering semantics
- requires monitoring to detect and respond to new hotspots

## anti_patterns
- use this when the root cause is a slow downstream dependency rather than skew
- use this when salting would break required ordering or query patterns
- ignoring the downside that can complicate queries and ordering semantics

## real_world_examples
- adding a random suffix to distribute counter increments across shards
- splitting a hot stream partition into multiple subkeys
