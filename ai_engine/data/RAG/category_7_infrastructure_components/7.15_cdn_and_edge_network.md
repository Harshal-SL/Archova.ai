# CDN and Edge Network


## chunk_id
- 7.15

## category
- infrastructure_components

## type
- infrastructure_component

## definition
- a globally distributed caching and delivery layer that serves content close to users to reduce latency and origin load.

## when_to_use
- serving static assets and media at global scale
- caching public api responses with appropriate variation keys
- offloading traffic spikes and mitigating origin overload

## when_not_to_use
- personalized or highly sensitive responses that must not be cached
- dynamic content with low cacheability and strict freshness requirements

## decision_signals
- need: serving static assets and media at global scale
- need: caching public api responses with appropriate variation keys
- willing to accept: caching mistakes can leak data or serve stale content

## advantages
- improves performance and reduces backend bandwidth
- provides resilience against traffic spikes and some attacks

## disadvantages
- caching mistakes can leak data or serve stale content
- invalidation and purge operations can be slow or expensive

## anti_patterns
- using this when personalized or highly sensitive responses that must not be cached
- using this when dynamic content with low cacheability and strict freshness requirements
- ignoring the downside that caching mistakes can leak data or serve stale content

## real_world_examples
- caching images and js bundles at the edge with long ttl and versioned urls
- using edge caching for public catalog endpoints with cache-control headers
