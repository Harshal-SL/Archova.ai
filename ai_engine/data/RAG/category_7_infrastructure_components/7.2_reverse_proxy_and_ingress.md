# Reverse Proxy and Ingress


## chunk_id
- 7.2

## category
- infrastructure_components

## type
- infrastructure_component

## definition
- an edge component that terminates client connections and forwards requests to internal services, often enforcing routing, tls, and policies.

## when_to_use
- consolidating tls termination and routing at the edge
- exposing multiple services behind one domain
- enforcing common policies like request limits and headers

## when_not_to_use
- simple internal-only services with no shared edge needs
- when an api gateway is already the single entry point and a proxy adds no value

## decision_signals
- need: consolidating tls termination and routing at the edge
- need: exposing multiple services behind one domain
- willing to accept: can become a bottleneck or single point of failure if not redundant

## advantages
- centralizes routing and tls configuration
- reduces direct exposure of internal services

## disadvantages
- can become a bottleneck or single point of failure if not redundant
- policy sprawl can make debugging harder

## anti_patterns
- using this when simple internal-only services with no shared edge needs
- use this when an api gateway is already the single entry point and a proxy adds no value
- ignoring the downside that can become a bottleneck or single point of failure if not redundant

## real_world_examples
- using an ingress controller to route /api to api servers and /static to a cdn
- applying gzip and request size limits at the reverse proxy
