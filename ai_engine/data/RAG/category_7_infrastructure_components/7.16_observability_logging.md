# Observability: Logging


## chunk_id
- 7.16

## category
- infrastructure_components

## type
- infrastructure_component

## definition
- centralized collection, storage, and querying of logs to support debugging, audits, and incident response.

## when_to_use
- diagnosing production incidents and user reports
- correlating events across services using request and trace ids
- auditing admin actions and security events

## when_not_to_use
- when logs would include sensitive data without redaction and access controls
- when cost constraints require minimal retention and sampling

## decision_signals
- need: diagnosing production incidents and user reports
- need: correlating events across services using request and trace ids
- willing to accept: can be expensive at high volume without sampling

## advantages
- improves mean time to recovery with searchable context
- supports compliance and forensic investigations

## disadvantages
- can be expensive at high volume without sampling
- poor structure makes logs hard to query and correlate

## anti_patterns
- use this when logs would include sensitive data without redaction and access controls
- use this when cost constraints require minimal retention and sampling
- ignoring the downside that can be expensive at high volume without sampling

## real_world_examples
- emitting structured json logs with request_id and user_id fields
- centralizing logs and retaining security events longer than debug logs
