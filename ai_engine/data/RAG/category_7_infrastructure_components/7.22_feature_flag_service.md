# Feature Flag Service


## chunk_id
- 7.22

## category
- infrastructure_components

## type
- infrastructure_component

## definition
- a centralized service that evaluates feature flags and targeting rules to control feature rollout without redeploying.

## when_to_use
- progressive delivery and staged rollouts
- enabling kill switches during incidents
- targeting features by tenant, region, or user cohort

## when_not_to_use
- when flags would be used as permanent configuration and never removed
- when flag evaluation latency would impact critical hot paths

## decision_signals
- need: progressive delivery and staged rollouts
- need: enabling kill switches during incidents
- willing to accept: flag debt accumulates if flags are not cleaned up

## advantages
- reduces deployment risk with controlled exposure
- supports fast rollback by flipping flags

## disadvantages
- flag debt accumulates if flags are not cleaned up
- misconfiguration can change behavior unexpectedly at runtime

## anti_patterns
- use this when flags would be used as permanent configuration and never removed
- use this when flag evaluation latency would impact critical hot paths
- ignoring the downside that flag debt accumulates if flags are not cleaned up

## real_world_examples
- enabling a new checkout flow for 5% of traffic before full rollout
- disabling a problematic integration via a kill switch during an outage
