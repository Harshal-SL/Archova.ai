# Secrets Management


## chunk_id
- 7.7

## category
- infrastructure_components

## type
- infrastructure_component

## definition
- securely storing and distributing secrets (api keys, passwords, certificates) with access control and rotation.

## when_to_use
- any system with credentials or encryption keys
- enforcing least privilege access to sensitive material
- automating secret rotation and auditing

## when_not_to_use
- when secrets are not present (rare) or can be replaced with short-lived identity tokens
- when secrets would be embedded in images or code (avoid)

## decision_signals
- need: any system with credentials or encryption keys
- need: enforcing least privilege access to sensitive material
- willing to accept: adds operational dependency and access management overhead

## advantages
- reduces secret leakage risk and supports rotation
- improves compliance through audit logs and access policies

## disadvantages
- adds operational dependency and access management overhead
- misconfiguration can cause widespread outages during rotation

## anti_patterns
- use this when secrets are not present (rare) or can be replaced with short-lived identity tokens
- use this when secrets would be embedded in images or code (avoid)
- ignoring the downside that adds operational dependency and access management overhead

## real_world_examples
- rotating database passwords and updating services via dynamic secret fetch
- issuing short-lived certificates for mTLS between services
