# Object Storage


## chunk_id
- 7.14

## category
- infrastructure_components

## type
- infrastructure_component

## definition
- storage for large immutable blobs (files, media, backups) addressed by keys, optimized for durability and cost.

## when_to_use
- storing user uploads, logs, backups, and artifacts
- decoupling large payloads from databases and message brokers
- serving static content through cdns

## when_not_to_use
- low-latency random reads that require database-like queries
- workloads that need frequent in-place updates of large objects

## decision_signals
- need: storing user uploads, logs, backups, and artifacts
- need: decoupling large payloads from databases and message brokers
- willing to accept: eventual consistency or listing semantics can be surprising

## advantages
- cost-effective, highly durable storage
- integrates well with cdns and lifecycle management

## disadvantages
- eventual consistency or listing semantics can be surprising
- requires careful access control for sensitive files

## anti_patterns
- using this when low-latency random reads that require database-like queries
- using this when workloads that need frequent in-place updates of large objects
- ignoring the downside that eventual consistency or listing semantics can be surprising

## real_world_examples
- storing invoices and receipts and serving via signed urls
- writing database backups to object storage with retention rules
