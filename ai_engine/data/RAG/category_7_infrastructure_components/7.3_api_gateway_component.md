# API Gateway


## chunk_id
- 7.3

## category
- infrastructure_components

## type
- infrastructure_component

## definition
- an infrastructure gateway component implemented with platforms like NGINX, Kong, Apigee, or AWS API Gateway to enforce edge routing, auth, throttling, and transformations.

## when_to_use
- centralizing cross-cutting concerns for many services
- providing a stable public api while internal services evolve
- implementing throttling and authentication consistently

## when_not_to_use
- small systems where direct service access is simpler
- when the gateway becomes a bottleneck for team autonomy and changes

## decision_signals
- need: centralizing cross-cutting concerns for many services
- need: providing a stable public api while internal services evolve
- willing to accept: can become a single point of failure or deployment bottleneck

## advantages
- simplifies clients and improves security posture
- enables consistent policies and observability at the edge

## disadvantages
- can become a single point of failure or deployment bottleneck
- adds latency and requires careful configuration governance

## anti_patterns
- using this for small systems where direct service access is simpler
- using this when the gateway becomes a bottleneck for team autonomy and changes
- ignoring the downside that it can become a single point of failure or deployment bottleneck

## real_world_examples
- implementing oauth validation and quotas with Kong plugins
- deploying managed routes, authorizers, and throttling in AWS API Gateway
