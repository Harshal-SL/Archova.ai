# Distributed Tracing


## chunk_id
- 7.18

## category
- infrastructure_components

## type
- infrastructure_component

## definition
- end-to-end tracing that links spans across services to visualize request paths and identify latency and error hotspots.

## when_to_use
- debugging latency issues in microservices and event-driven systems
- understanding dependencies and critical paths
- verifying performance changes after deployments

## when_not_to_use
- when overhead is unacceptable and sampling cannot be used
- when sensitive metadata would be captured without governance

## decision_signals
- need: debugging latency issues in microservices and event-driven systems
- need: understanding dependencies and critical paths
- willing to accept: instrumentation and context propagation require consistency

## advantages
- improves root cause analysis for distributed systems
- highlights bottlenecks and unexpected call paths

## disadvantages
- instrumentation and context propagation require consistency
- storage costs can be high without sampling and retention controls

## anti_patterns
- use this when overhead is unacceptable and sampling cannot be used
- use this when sensitive metadata would be captured without governance
- ignoring the downside that instrumentation and context propagation require consistency

## real_world_examples
- tracing a checkout request through gateway, payments, inventory, and notifications
- linking async message processing spans back to the originating request
