# Service Discovery


## chunk_id
- 7.4

## category
- infrastructure_components

## type
- infrastructure_component

## definition
- an infrastructure service-discovery component implemented with tools like Consul, Eureka, ZooKeeper, or orchestrator-native discovery to locate healthy instances.

## when_to_use
- microservices with frequently changing instance addresses
- autoscaling environments where instances come and go
- reducing hard-coded configuration for service endpoints

## when_not_to_use
- static deployments with fixed addresses and low change frequency
- when a service mesh or orchestrator already provides discovery implicitly

## decision_signals
- need: microservices with frequently changing instance addresses
- need: autoscaling environments where instances come and go
- willing to accept: registry outages can affect service-to-service communication

## advantages
- enables resilient routing to healthy instances
- supports dynamic scaling and failover

## disadvantages
- registry outages can affect service-to-service communication
- inconsistent health checks can cause flapping and instability

## anti_patterns
- using this for static deployments with fixed addresses and low change frequency
- using this when a service mesh or orchestrator already provides discovery implicitly
- ignoring the downside that registry outages can affect service-to-service communication

## real_world_examples
- consul catalog + health checks used for service endpoint resolution
- eureka client/server registration for autoscaled spring services
