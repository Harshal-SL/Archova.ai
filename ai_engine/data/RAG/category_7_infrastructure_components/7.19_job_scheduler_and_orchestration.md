# Job Scheduler and Orchestration


## chunk_id
- 7.19

## category
- infrastructure_components

## type
- infrastructure_component

## definition
- infrastructure that runs background jobs on schedules or triggers, handling retries, concurrency, and failure recovery.

## when_to_use
- batch processing, backfills, and periodic maintenance jobs
- orchestrating multi-step workflows across services
- controlling concurrency for expensive background tasks

## when_not_to_use
- simple tasks that can run inline without impacting latency
- when event-driven triggers are sufficient and schedules add complexity

## decision_signals
- need: batch processing, backfills, and periodic maintenance jobs
- need: orchestrating multi-step workflows across services
- willing to accept: scheduling drift and retries can cause duplicate work

## advantages
- improves reliability of background workloads with retries and monitoring
- enables controlled concurrency and prioritization

## disadvantages
- scheduling drift and retries can cause duplicate work
- orchestration logic can become complex and hard to evolve

## anti_patterns
- using this when simple tasks that can run inline without impacting latency
- use this when event-driven triggers are sufficient and schedules add complexity
- ignoring the downside that scheduling drift and retries can cause duplicate work

## real_world_examples
- nightly aggregation jobs with checkpointing and alerting
- orchestrating a data pipeline with step retries and timeouts
