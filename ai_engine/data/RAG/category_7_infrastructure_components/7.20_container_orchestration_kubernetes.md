# Container Orchestration (Kubernetes)


## chunk_id
- 7.20

## category
- infrastructure_components

## type
- infrastructure_component

## definition
- a platform for deploying and operating containerized workloads with scheduling, service discovery, autoscaling, and rolling updates.

## when_to_use
- many services requiring consistent deployment and scaling primitives
- needing self-healing, autoscaling, and declarative configuration
- standardizing operations across teams and environments

## when_not_to_use
- small systems where managed platform services are simpler
- teams without capacity to operate clusters safely and securely

## decision_signals
- need: many services requiring consistent deployment and scaling primitives
- need: needing self-healing, autoscaling, and declarative configuration
- willing to accept: operational complexity and steep learning curve

## advantages
- provides standardized primitives for scaling and resilience
- supports rolling updates, health checks, and resource isolation

## disadvantages
- operational complexity and steep learning curve
- misconfiguration can create security and reliability incidents

## anti_patterns
- using this when small systems where managed platform services are simpler
- using this when teams without capacity to operate clusters safely and securely
- ignoring the downside that operational complexity and steep learning curve

## real_world_examples
- deploying microservices with horizontal pod autoscaling
- using ingress controllers and service discovery for internal routing
