# Caching Layer


## chunk_id
- 7.11

## category
- infrastructure_components

## type
- infrastructure_component

## definition
- a shared cache service that stores frequently accessed data to reduce latency and load on databases and backends.

## when_to_use
- read-heavy workloads with hot keys
- protecting databases from repeated reads
- reducing tail latency for user-facing endpoints

## when_not_to_use
- when data cannot be cached safely due to correctness or privacy constraints
- when cache misses would overload the origin and no stampede controls exist

## decision_signals
- need: read-heavy workloads with hot keys
- need: protecting databases from repeated reads
- willing to accept: introduces staleness and invalidation complexity

## advantages
- improves read latency and reduces origin load
- enables higher throughput with the same database capacity

## disadvantages
- introduces staleness and invalidation complexity
- cache outages can amplify load on the origin

## anti_patterns
- use this when data cannot be cached safely due to correctness or privacy constraints
- use this when cache misses would overload the origin and no stampede controls exist
- ignoring the downside that introduces staleness and invalidation complexity

## real_world_examples
- caching product details in redis with ttl
- caching authorization decisions with short expiry
