# Service Discovery Scaling Challenges


## chunk_id
- 7.27

## category
- infrastructure_components

## type
- infrastructure_component

## definition
- scaling service discovery control planes and client resolution behavior under large fleets, frequent churn, and multi-region traffic.

## when_to_use
- clusters with high instance churn and frequent autoscaling
- large microservice fleets with many lookups per request path
- multi-region environments with locality-aware routing requirements

## when_not_to_use
- static service topologies with rare endpoint changes
- very small deployments where dns records are enough

## decision_signals
- need: clusters with high instance churn and frequent autoscaling
- need: large microservice fleets with many lookups per request path
- willing to accept: additional control plane and caching complexity

## advantages
- prevents lookup storms and stale endpoint routing
- improves failover behavior under partial control-plane outages

## disadvantages
- additional control plane and caching complexity
- consistency lag between registration and client view can cause errors

## anti_patterns
- forcing clients to query registry on every request
- using identical ttl and refresh policy for all services
- ignoring zone and region affinity in endpoint selection

## real_world_examples
- client-side endpoint cache with jittered refresh and circuit breaking
- tiered discovery (local agent, regional cache, global registry)
