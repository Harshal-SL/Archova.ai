# Rolling Deployments


## chunk_id
- 8.1

## category
- deployment_strategies

## type
- deployment_strategy

## definition
- updating instances gradually by replacing a subset at a time while keeping the service available.

## when_to_use
- stateless services behind a load balancer
- minimizing downtime without needing full parallel environments
- frequent releases where simplicity is important

## when_not_to_use
- stateful systems without safe rolling upgrade paths
- releases requiring instant cutover or strict version consistency

## decision_signals
- need: stateless services behind a load balancer
- need: minimizing downtime without needing full parallel environments
- willing to accept: mixed versions can cause compatibility issues

## advantages
- reduces risk by limiting blast radius per step
- uses existing infrastructure without duplicate stacks

## disadvantages
- mixed versions can cause compatibility issues
- rollback can be slow if many instances already updated

## anti_patterns
- using this when stateful systems without safe rolling upgrade paths
- using this when releases requiring instant cutover or strict version consistency
- ignoring the downside that mixed versions can cause compatibility issues

## real_world_examples
- updating 10% of api pods at a time with readiness checks
- rolling out a new worker version while keeping old workers running
