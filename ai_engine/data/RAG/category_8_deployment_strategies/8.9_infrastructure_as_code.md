# Infrastructure as Code


## chunk_id
- 8.9

## category
- deployment_strategies

## type
- deployment_strategy

## definition
- managing infrastructure through version-controlled definitions that are reviewed, tested, and deployed like application code.

## when_to_use
- provisioning repeatable environments and reducing drift
- enforcing policy and security controls via review and automation
- enabling reproducible disaster recovery and scaling

## when_not_to_use
- one-off experiments where automation overhead is not worth it
- when teams cannot manage state and approvals safely

## decision_signals
- need: provisioning repeatable environments and reducing drift
- need: enforcing policy and security controls via review and automation
- willing to accept: requires tooling, state management, and discipline

## advantages
- improves reproducibility and auditability
- reduces manual configuration errors and drift

## disadvantages
- requires tooling, state management, and discipline
- mistakes can be propagated quickly if reviews are weak

## anti_patterns
- using this when one-off experiments where automation overhead is not worth it
- use this when teams cannot manage state and approvals safely
- ignoring the downside that requires tooling, state management, and discipline

## real_world_examples
- defining networks, load balancers, and clusters in code and deploying via pipelines
- reviewing infra changes through pull requests with automated validation
