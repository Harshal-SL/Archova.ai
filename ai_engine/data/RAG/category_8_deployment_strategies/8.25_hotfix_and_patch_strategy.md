# Hotfix and Patch Strategy


## chunk_id
- 8.25

## category
- deployment_strategies

## type
- deployment_strategy

## definition
- a controlled approach for urgent production fixes that balances speed with safety, traceability, and follow-up cleanup.

## when_to_use
- security patches and critical production defects
- urgent fixes that cannot wait for the normal release train
- mitigating incidents with minimal scope changes

## when_not_to_use
- routine feature work that should follow standard delivery processes
- when the fix requires broad architectural changes better handled as a planned release

## decision_signals
- need: security patches and critical production defects
- need: urgent fixes that cannot wait for the normal release train
- willing to accept: can introduce instability if rushed and under-tested

## advantages
- reduces time to mitigate critical issues
- maintains traceability and process even under pressure

## disadvantages
- can introduce instability if rushed and under-tested
- creates branch and version management complexity

## anti_patterns
- using this when routine feature work that should follow standard delivery processes
- use this when the fix requires broad architectural changes better handled as a planned release
- ignoring the downside that can introduce instability if rushed and under-tested

## real_world_examples
- patching a critical auth bug with a minimal diff and immediate canary rollout
- releasing an emergency config change behind a feature flag with rollback
