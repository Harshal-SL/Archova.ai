# Canary Releases


## chunk_id
- 8.3

## category
- deployment_strategies

## type
- deployment_strategy

## definition
- exposing a new version to a small percentage of traffic first, then gradually increasing as metrics confirm safety.

## when_to_use
- reducing risk for user-facing services
- validating performance and error rate changes under real load
- rolling out changes that might impact a subset of users

## when_not_to_use
- when traffic is too low to detect issues statistically
- when the system cannot run mixed versions safely

## decision_signals
- need: reducing risk for user-facing services
- need: validating performance and error rate changes under real load
- willing to accept: requires routing control and good observability

## advantages
- limits blast radius and enables early detection
- supports data-driven rollout decisions

## disadvantages
- requires routing control and good observability
- can miss rare issues if canary traffic is not representative

## anti_patterns
- use this when traffic is too low to detect issues statistically
- use this when the system cannot run mixed versions safely
- ignoring the downside that requires routing control and good observability

## real_world_examples
- routing 1% of requests to a new api version and monitoring p95 latency
- canarying a new recommendation model for a small user cohort
