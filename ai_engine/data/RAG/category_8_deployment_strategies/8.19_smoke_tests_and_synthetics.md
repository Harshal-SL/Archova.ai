# Smoke Tests and Synthetics


## chunk_id
- 8.19

## category
- deployment_strategies

## type
- deployment_strategy

## definition
- lightweight automated checks that validate critical user journeys before and after deployments, often from multiple regions.

## when_to_use
- preventing broken deploys from reaching broad traffic
- monitoring availability independently of internal telemetry
- validating dns, tls, and edge routing changes

## when_not_to_use
- when tests are slow and flaky, creating noise and blocking releases
- when synthetics would trigger real side effects without safe test data

## decision_signals
- need: preventing broken deploys from reaching broad traffic
- need: monitoring availability independently of internal telemetry
- willing to accept: limited coverage compared to full integration tests

## advantages
- catches obvious breakages quickly
- provides external perspective on availability and latency

## disadvantages
- limited coverage compared to full integration tests
- requires careful test data management and isolation

## anti_patterns
- use this when tests are slow and flaky, creating noise and blocking releases
- use this when synthetics would trigger real side effects without safe test data
- ignoring the downside that limited coverage compared to full integration tests

## real_world_examples
- synthetic checkout flow against a test tenant every minute
- smoke tests on green environment before a blue-green cutover
