# Blue-Green Deployments


## chunk_id
- 8.2

## category
- deployment_strategies

## type
- deployment_strategy

## definition
- running two production environments (blue and green) and switching traffic from old to new in a controlled cutover.

## when_to_use
- needing fast rollback by switching traffic back
- releases with high risk or major changes
- deployments requiring full environment validation before exposure

## when_not_to_use
- when running duplicate environments is too costly
- when data migrations cannot be made compatible for fast rollback

## decision_signals
- need: needing fast rollback by switching traffic back
- need: releases with high risk or major changes
- willing to accept: doubles infrastructure during deployment

## advantages
- enables near-instant rollback
- supports full validation of the new stack before cutover

## disadvantages
- doubles infrastructure during deployment
- database and stateful components can complicate true blue-green

## anti_patterns
- use this when running duplicate environments is too costly
- use this when data migrations cannot be made compatible for fast rollback
- ignoring the downside that doubles infrastructure during deployment

## real_world_examples
- deploying a new api version to green and switching the load balancer target
- validating end-to-end smoke tests on green before traffic cutover
