# Progressive Delivery


## chunk_id
- 8.4

## category
- deployment_strategies

## type
- deployment_strategy

## definition
- deploying changes incrementally using automated analysis, traffic shifting, and staged validation across environments and cohorts.

## when_to_use
- high-frequency releases with tight reliability requirements
- automating rollout decisions based on metrics
- coordinating multiple changes safely over time

## when_not_to_use
- small systems where a simple deploy is sufficient
- when observability is weak and automated decisions would be unsafe

## decision_signals
- need: high-frequency releases with tight reliability requirements
- need: automating rollout decisions based on metrics
- willing to accept: tooling and pipeline complexity can be significant

## advantages
- reduces risk with measurable, automated guardrails
- improves deployment velocity without sacrificing reliability

## disadvantages
- tooling and pipeline complexity can be significant
- requires mature metrics and clear slos to drive decisions

## anti_patterns
- using this when small systems where a simple deploy is sufficient
- use this when observability is weak and automated decisions would be unsafe
- ignoring the downside that tooling and pipeline complexity can be significant

## real_world_examples
- automated canary analysis that promotes or aborts based on error rate deltas
- staged rollout across ring environments before global release
