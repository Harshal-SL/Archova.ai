# Shadow Traffic


## chunk_id
- 8.6

## category
- deployment_strategies

## type
- deployment_strategy

## definition
- duplicating production traffic to a new system version without impacting user responses, to validate behavior under real load.

## when_to_use
- validating performance and correctness of a new stack
- testing migration paths and compatibility safely
- comparing outputs between old and new implementations

## when_not_to_use
- when shadowing would process sensitive data in an unapproved environment
- when side effects cannot be prevented reliably

## decision_signals
- need: validating performance and correctness of a new stack
- need: testing migration paths and compatibility safely
- willing to accept: doubles load and can increase infrastructure cost

## advantages
- provides high-fidelity validation with real traffic patterns
- reduces risk for major migrations and rewrites

## disadvantages
- doubles load and can increase infrastructure cost
- requires strict side-effect isolation to avoid duplicate actions

## anti_patterns
- use this when shadowing would process sensitive data in an unapproved environment
- use this when side effects cannot be prevented reliably
- ignoring the downside that doubles load and can increase infrastructure cost

## real_world_examples
- sending a copy of requests to a new search service and comparing results offline
- shadowing checkout requests to validate latency under peak load
