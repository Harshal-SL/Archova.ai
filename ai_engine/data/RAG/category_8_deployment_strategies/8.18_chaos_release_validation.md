# Chaos Release Validation


## chunk_id
- 8.18

## category
- deployment_strategies

## type
- deployment_strategy

## definition
- validating releases by injecting controlled failures to ensure resilience mechanisms work under real conditions.

## when_to_use
- systems with strict reliability requirements
- verifying fallback behavior, retries, and timeouts during deployments
- preventing regressions in resilience after changes

## when_not_to_use
- early-stage systems without safe blast radius controls
- when on-call coverage is not available to respond to experiments

## decision_signals
- need: systems with strict reliability requirements
- need: verifying fallback behavior, retries, and timeouts during deployments
- willing to accept: can cause incidents if experiments are poorly controlled

## advantages
- increases confidence that resilience patterns actually work
- finds hidden dependencies and brittle assumptions

## disadvantages
- can cause incidents if experiments are poorly controlled
- requires careful design, guardrails, and observability

## anti_patterns
- using this when early-stage systems without safe blast radius controls
- use this when on-call coverage is not available to respond to experiments
- ignoring the downside that can cause incidents if experiments are poorly controlled

## real_world_examples
- injecting latency into a dependency during a canary to validate timeouts
- terminating a subset of instances to verify autoscaling and failover
