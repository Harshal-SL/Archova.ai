# Zero-Downtime Database Migrations


## chunk_id
- 8.13

## category
- deployment_strategies

## type
- deployment_strategy

## definition
- evolving database schema and data without outages by using compatible changes, backfills, and phased cutovers.

## when_to_use
- large databases where maintenance windows are not acceptable
- services requiring continuous availability
- multi-service environments where deploy order cannot be guaranteed

## when_not_to_use
- when a short planned outage window is acceptable and simpler
- when the schema change is too large without a safe intermediate state

## decision_signals
- need: large databases where maintenance windows are not acceptable
- need: services requiring continuous availability
- willing to accept: requires careful planning and multi-step execution

## advantages
- avoids downtime and reduces user impact
- supports continuous delivery with database evolution

## disadvantages
- requires careful planning and multi-step execution
- backfills and dual-writes can increase load and complexity

## anti_patterns
- use this when a short planned outage window is acceptable and simpler
- use this when the schema change is too large without a safe intermediate state
- ignoring the downside that requires careful planning and multi-step execution

## real_world_examples
- add nullable column, deploy code that writes both, backfill, then switch reads
- creating a new table and migrating traffic gradually while keeping old table in sync
