# GitOps


## chunk_id
- 8.10

## category
- deployment_strategies

## type
- deployment_strategy

## definition
- operating deployments by using git as the source of truth and controllers that reconcile the desired state into environments.

## when_to_use
- kubernetes and declarative platforms with clear desired state
- improving auditability and repeatability of releases
- reducing manual changes and configuration drift

## when_not_to_use
- imperative deployment environments without reliable reconciliation
- when secrets management is not ready for git-driven workflows

## decision_signals
- need: kubernetes and declarative platforms with clear desired state
- need: improving auditability and repeatability of releases
- willing to accept: requires strong access controls and secret handling

## advantages
- improves traceability of changes with git history
- enables automated drift detection and reconciliation

## disadvantages
- requires strong access controls and secret handling
- debugging reconciliation loops and controllers can be complex

## anti_patterns
- using this when imperative deployment environments without reliable reconciliation
- use this when secrets management is not ready for git-driven workflows
- ignoring the downside that requires strong access controls and secret handling

## real_world_examples
- updating a git repo to change a deployment image tag and letting a controller apply it
- detecting and reverting manual changes to cluster config automatically
