# Feature Flags in Deployments


## chunk_id
- 8.5

## category
- deployment_strategies

## type
- deployment_strategy

## definition
- decoupling code deployment from feature release by toggling behavior at runtime using flags and targeting rules.

## when_to_use
- separating rollout risk from deploy risk
- enabling kill switches for fast mitigation
- targeting features by tenant, region, or cohort

## when_not_to_use
- when flags would be used as permanent configuration and never removed
- when runtime toggles would violate compliance change controls

## decision_signals
- need: separating rollout risk from deploy risk
- need: enabling kill switches for fast mitigation
- willing to accept: increases testing matrix and can cause flag debt

## advantages
- reduces risk by allowing gradual exposure and fast rollback
- supports experimentation and controlled releases

## disadvantages
- increases testing matrix and can cause flag debt
- misconfiguration can change behavior instantly across production

## anti_patterns
- use this when flags would be used as permanent configuration and never removed
- use this when runtime toggles would violate compliance change controls
- ignoring the downside that increases testing matrix and can cause flag debt

## real_world_examples
- deploying code globally but enabling the feature for 5% of users
- disabling a new integration quickly during an incident
