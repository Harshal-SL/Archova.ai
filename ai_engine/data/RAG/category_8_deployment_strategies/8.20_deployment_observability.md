# Deployment Observability


## chunk_id
- 8.20

## category
- deployment_strategies

## type
- deployment_strategy

## definition
- measuring deployment impact using release markers, per-version metrics, and logs/traces to detect regressions quickly.

## when_to_use
- canary and rolling deploys where mixed versions exist
- enforcing slos and catching performance regressions
- reducing time to detect and rollback bad releases

## when_not_to_use
- when telemetry is missing and adding markers would not be used
- when low-risk systems do not justify detailed release analysis

## decision_signals
- need: canary and rolling deploys where mixed versions exist
- need: enforcing slos and catching performance regressions
- willing to accept: requires consistent release metadata and instrumentation

## advantages
- shortens time to detect and diagnose release issues
- enables data-driven promotion and rollback decisions

## disadvantages
- requires consistent release metadata and instrumentation
- increases metric cardinality if labels are uncontrolled

## anti_patterns
- use this when telemetry is missing and adding markers would not be used
- use this when low-risk systems do not justify detailed release analysis
- ignoring the downside that requires consistent release metadata and instrumentation

## real_world_examples
- tagging metrics with build_version and environment for per-release dashboards
- adding deployment annotations to correlate latency spikes with releases
