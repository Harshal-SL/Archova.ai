# Secret Rotation in Deployments


## chunk_id
- 8.21

## category
- deployment_strategies

## type
- deployment_strategy

## definition
- rotating credentials and keys safely by coordinating rollout, dual-validity windows, and automated verification.

## when_to_use
- scheduled key rotation for compliance and security hygiene
- responding to suspected credential compromise
- migrating to new certificates or signing keys

## when_not_to_use
- when services cannot support dual credentials and rotation would be an outage
- when rotation procedures are untested and on-call coverage is unavailable

## decision_signals
- need: scheduled key rotation for compliance and security hygiene
- need: responding to suspected credential compromise
- willing to accept: rotation can cause outages if dependencies are not updated in time

## advantages
- reduces blast radius of leaked credentials
- improves security posture with regular key hygiene

## disadvantages
- rotation can cause outages if dependencies are not updated in time
- increases operational complexity across many services

## anti_patterns
- use this when services cannot support dual credentials and rotation would be an outage
- use this when rotation procedures are untested and on-call coverage is unavailable
- ignoring the downside that rotation can cause outages if dependencies are not updated in time

## real_world_examples
- rotating database passwords with a dual-password grace period
- rolling new tls certificates across gateways and services before expiry
