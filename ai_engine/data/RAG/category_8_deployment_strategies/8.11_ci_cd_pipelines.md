# CI/CD Pipelines


## chunk_id
- 8.11

## category
- deployment_strategies

## type
- deployment_strategy

## definition
- automated workflows that build, test, and deploy changes consistently from source control to production.

## when_to_use
- frequent releases requiring repeatability and quality gates
- reducing manual deployment steps and human error
- enforcing security and compliance checks consistently

## when_not_to_use
- one-off prototypes where pipeline overhead is unjustified
- when deployments must be fully manual due to strict change controls (still automate build/test)

## decision_signals
- need: frequent releases requiring repeatability and quality gates
- need: reducing manual deployment steps and human error
- willing to accept: pipeline complexity can grow quickly with many environments

## advantages
- improves reliability and speed of releases
- enables consistent validation and rollback processes

## disadvantages
- pipeline complexity can grow quickly with many environments
- flaky tests can block delivery and erode trust

## anti_patterns
- using this when one-off prototypes where pipeline overhead is unjustified
- use this when deployments must be fully manual due to strict change controls (still automate build/test)
- ignoring the downside that pipeline complexity can grow quickly with many environments

## real_world_examples
- running unit, integration, and smoke tests before canary promotion
- building once and deploying the same artifact across dev, staging, and prod
