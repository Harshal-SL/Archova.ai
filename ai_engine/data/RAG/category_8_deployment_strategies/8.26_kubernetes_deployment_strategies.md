# Kubernetes Deployment Strategies


## chunk_id
- 8.26

## category
- deployment_strategies

## type
- deployment_strategy

## definition
- applying rollout techniques in kubernetes such as rolling, canary, blue-green, and progressive delivery with workload- and risk-aware controls.

## when_to_use
- frequent kubernetes releases across many services
- need to minimize blast radius for production changes
- strict slos requiring automatic rollback on regressions

## when_not_to_use
- low-frequency manual releases with small user impact
- teams without deployment observability and rollback automation

## decision_signals
- need: frequent kubernetes releases across many services
- need: strict slos requiring automatic rollback on regressions
- willing to accept: higher pipeline and operational complexity

## advantages
- reduces deployment risk while preserving release velocity
- supports workload-specific rollout policies

## disadvantages
- higher pipeline and operational complexity
- misconfigured probes and metrics can cause false rollbacks

## anti_patterns
- using identical rollout thresholds for all services
- canarying without representative traffic slices
- rolling database and app changes without compatibility plan

## real_world_examples
- canarying api pods with automated abort on p95 latency regression
- blue-green cutover for high-risk stateful migration windows
