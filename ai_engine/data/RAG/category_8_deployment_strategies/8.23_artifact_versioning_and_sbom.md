# Artifact Versioning and SBOM


## chunk_id
- 8.23

## category
- deployment_strategies

## type
- deployment_strategy

## definition
- versioning build outputs and producing a software bill of materials so deployments are traceable and supply chain risks are visible.

## when_to_use
- regulated environments requiring provenance and audit trails
- incident response needing fast identification of vulnerable components
- promoting the same artifact across environments reliably

## when_not_to_use
- throwaway prototypes with no distribution or compliance requirements
- when tooling cannot be secured and would expose sensitive dependency metadata

## decision_signals
- need: regulated environments requiring provenance and audit trails
- need: incident response needing fast identification of vulnerable components
- willing to accept: adds build and release pipeline overhead

## advantages
- improves traceability from code to running versions
- supports vulnerability management and compliance reporting

## disadvantages
- adds build and release pipeline overhead
- requires secure storage and access controls for artifacts and metadata

## anti_patterns
- using this when throwaway prototypes with no distribution or compliance requirements
- use this when tooling cannot be secured and would expose sensitive dependency metadata
- ignoring the downside that adds build and release pipeline overhead

## real_world_examples
- tagging container images with immutable digests and storing sboms alongside
- scanning sboms to identify affected services during a cve disclosure
