# CDN First Architecture


## chunk_id
- 1.56

## category
- architecture_patterns

## type
- architecture

## definition
- an architecture that serves content and requests through a cdn layer first to reduce latency and offload origin services.

## when_to_use
- global audiences consuming static and cacheable dynamic content
- protecting origins from traffic spikes and ddos patterns
- reducing latency via edge caching and edge routing

## when_not_to_use
- highly personalized responses that cannot be cached safely
- workloads requiring strict end-to-end encryption termination only at origin

## decision_signals
- need: global audiences consuming static and cacheable dynamic content
- need: protecting origins from traffic spikes and ddos patterns
- willing to accept: cache invalidation and consistency can be complex

## advantages
- improves latency by serving from edge locations
- reduces origin load and smooths burst traffic

## disadvantages
- cache invalidation and consistency can be complex
- can introduce debugging challenges due to edge behavior and caching layers

## anti_patterns
- using this when highly personalized responses that cannot be cached safely
- using this when workloads requiring strict end-to-end encryption termination only at origin
- ignoring the downside that cache invalidation and consistency can be complex

## real_world_examples
- static site assets cached at the edge
- api responses cached with surrogate keys and ttl
