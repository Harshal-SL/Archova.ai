# Sidecar Pattern


## chunk_id
- 1.33

## category
- architecture_patterns

## type
- pattern

## definition
- a pattern where a helper process runs alongside an app instance to provide networking, logging, or security capabilities.

## when_to_use
- injecting cross-cutting concerns without changing app code
- service mesh data plane proxies for mTLS and routing
- per-pod agents for metrics and log shipping

## when_not_to_use
- simple deployments where a shared library is sufficient
- when sidecar overhead violates latency or cost constraints

## decision_signals
- need: injecting cross-cutting concerns without changing app code
- need: service mesh data plane proxies for mTLS and routing
- willing to accept: increases resource usage and operational complexity per instance

## advantages
- standardizes cross-cutting behavior across many services
- reduces application code changes for infra capabilities

## disadvantages
- increases resource usage and operational complexity per instance
- debugging becomes harder due to multi-process interactions

## anti_patterns
- using this when simple deployments where a shared library is sufficient
- use this when sidecar overhead violates latency or cost constraints
- ignoring the downside that increases resource usage and operational complexity per instance

## real_world_examples
- envoy sidecar proxies in istio
- fluent bit sidecars for log forwarding
