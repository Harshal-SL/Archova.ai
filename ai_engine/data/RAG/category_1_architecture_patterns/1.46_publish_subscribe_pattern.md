# Publish-Subscribe Pattern


## chunk_id
- 1.46

## category
- architecture_patterns

## type
- pattern

## definition
- a messaging pattern where publishers emit events to a topic and multiple subscribers consume independently.

## when_to_use
- decoupling producers from multiple downstream consumers
- fan-out updates like cache invalidation and notifications
- integrating services without direct synchronous calls

## when_not_to_use
- workflows requiring strict request-response and immediate results
- when message ordering and exactly-once are mandatory end-to-end

## decision_signals
- need: decoupling producers from multiple downstream consumers
- need: fan-out updates like cache invalidation and notifications
- willing to accept: increases distributed tracing and debugging complexity

## advantages
- reduces coupling and enables independent scaling of consumers
- supports extensibility by adding subscribers without changing producers

## disadvantages
- increases distributed tracing and debugging complexity
- requires event schema governance and versioning discipline

## anti_patterns
- using this when workflows requiring strict request-response and immediate results
- use this when message ordering and exactly-once are mandatory end-to-end
- ignoring the downside that increases distributed tracing and debugging complexity

## real_world_examples
- order-created events triggering email and fulfillment handlers
- cache invalidation broadcasts on entity updates
