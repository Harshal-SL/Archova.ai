# Write-Through Cache Pattern


## chunk_id
- 1.43

## category
- architecture_patterns

## type
- pattern

## definition
- a caching pattern where writes update the cache and the backing store synchronously in the same request path.

## when_to_use
- systems needing high cache hit rates after writes
- data that must be immediately available in cache for reads
- simplifying cache coherence by writing through a single path

## when_not_to_use
- high write throughput where synchronous cache writes add latency
- when cache is optional and should not block critical writes

## decision_signals
- need: systems needing high cache hit rates after writes
- need: data that must be immediately available in cache for reads
- willing to accept: increases write latency and dependency on cache availability

## advantages
- reduces stale cache risk after updates
- improves read latency by keeping cache warm

## disadvantages
- increases write latency and dependency on cache availability
- can amplify writes and increase cache cost

## anti_patterns
- using this when high write throughput where synchronous cache writes add latency
- use this when cache is optional and should not block critical writes
- ignoring the downside that increases write latency and dependency on cache availability

## real_world_examples
- updating user session state in cache and database
- writing product inventory updates through a cache layer
