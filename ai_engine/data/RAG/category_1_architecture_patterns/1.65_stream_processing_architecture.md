# Stream Processing Architecture


## chunk_id
- 1.65

## category
- architecture_patterns

## type
- architecture

## definition
- an architecture that processes continuous event streams in near realtime to compute aggregates, detect patterns, and update derived state.

## when_to_use
- realtime analytics, fraud detection, and monitoring pipelines
- reacting to events with low latency and continuous computation
- maintaining materialized views from event streams

## when_not_to_use
- workloads better handled as scheduled batch jobs
- when event ordering, late data, and state management are too complex for the team

## decision_signals
- need: realtime analytics, fraud detection, and monitoring pipelines
- need: reacting to events with low latency and continuous computation
- willing to accept: requires careful handling of state, windows, and exactly-once semantics

## advantages
- provides low-latency insights and reactions to events
- scales horizontally across partitions and consumer groups

## disadvantages
- requires careful handling of state, windows, and exactly-once semantics
- operational complexity for scaling, backpressure, and replay

## anti_patterns
- using this when workloads better handled as scheduled batch jobs
- use this when event ordering, late data, and state management are too complex for the team
- ignoring the downside that requires careful handling of state, windows, and exactly-once semantics

## real_world_examples
- realtime alerting from clickstream events
- stream aggregation for per-minute metrics dashboards
