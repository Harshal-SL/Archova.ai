# Event-Driven Architecture


## chunk_id
- 1.4

## category
- architecture_patterns

## type
- architecture

## definition
- an architecture where components communicate through events instead of direct synchronous calls.

## when_to_use
- real-time systems
- asynchronous workflows
- high scale systems
- event-based processing

## when_not_to_use
- simple CRUD applications
- systems needing strong consistency

## decision_signals
- need: real-time systems
- need: asynchronous workflows
- willing to accept: debugging complexity

## advantages
- loose coupling
- high scalability
- asynchronous processing
- improved resilience

## disadvantages
- debugging complexity
- event ordering issues
- eventual consistency

## anti_patterns
- using this when simple CRUD applications
- using this when systems needing strong consistency
- ignoring the downside that debugging complexity

## real_world_examples
- Uber event system
- Kafka pipelines
