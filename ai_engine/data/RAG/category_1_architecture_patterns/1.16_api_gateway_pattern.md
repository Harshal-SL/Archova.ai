# API Gateway Pattern


## chunk_id
- 1.16

## category
- architecture_patterns

## type
- pattern

## definition
- an architectural pattern that defines a unified entry point for client traffic, routing, aggregation, and policy enforcement across multiple backend services.

## when_to_use
- microservices architecture
- multiple backend services
- client-specific aggregation and orchestration needs

## when_not_to_use
- monolithic systems

## decision_signals
- need: microservices architecture
- need: multiple backend services
- willing to accept: single point of failure

## advantages
- centralized control
- security management
- simplified client communication

## disadvantages
- single point of failure
- added latency

## anti_patterns
- using this for monolithic systems
- ignoring the downside that it can become a single point of failure

## real_world_examples
- gateway-based api composition for mobile and web clients
- centralized auth, versioning, and contract governance at the edge

- Prefer when many clients and services require a single policy and routing boundary. Avoid when direct service access is simpler and gateway indirection adds unnecessary complexity.
