# Kappa Architecture


## chunk_id
- 1.31

## category
- architecture_patterns

## type
- architecture

## definition
- a streaming-first architecture where a single event stream powers both realtime processing and historical reprocessing.

## when_to_use
- event streams as the primary source of truth
- analytics pipelines needing replay and backfills
- teams standardizing on one processing stack

## when_not_to_use
- workloads requiring heavy batch-only computations
- teams without strong event schema and retention governance

## decision_signals
- need: event streams as the primary source of truth
- need: analytics pipelines needing replay and backfills
- willing to accept: depends on long retention and reliable replayable streams

## advantages
- removes duplicated batch and speed layer logic
- supports replay for recovery and re-derivation

## disadvantages
- depends on long retention and reliable replayable streams
- reprocessing can be slow and resource intensive

## anti_patterns
- using this when workloads requiring heavy batch-only computations
- using this when teams without strong event schema and retention governance
- ignoring the downside that depends on long retention and reliable replayable streams

## real_world_examples
- kafka-based pipelines using stream processors for realtime and replay
- clickstream analytics rebuilt from event logs
