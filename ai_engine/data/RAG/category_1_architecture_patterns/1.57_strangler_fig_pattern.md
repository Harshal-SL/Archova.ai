# Strangler Fig Pattern


## chunk_id
- 1.57

## category
- architecture_patterns

## type
- pattern

## definition
- a modernization pattern that incrementally replaces a legacy system by routing parts of functionality to new services over time.

## when_to_use
- large monoliths that cannot be replaced in a single rewrite
- migrating traffic gradually to reduce risk
- carving out bounded contexts into new components

## when_not_to_use
- when a small system can be replaced quickly and safely
- when legacy coupling prevents incremental extraction without major rework

## decision_signals
- need: large monoliths that cannot be replaced in a single rewrite
- need: migrating traffic gradually to reduce risk
- willing to accept: requires running legacy and new systems in parallel for a time

## advantages
- reduces migration risk via incremental delivery
- enables continuous value delivery while modernizing

## disadvantages
- requires running legacy and new systems in parallel for a time
- routing and data consistency across old and new can be complex

## anti_patterns
- use this when a small system can be replaced quickly and safely
- use this when legacy coupling prevents incremental extraction without major rework
- ignoring the downside that requires running legacy and new systems in parallel for a time

## real_world_examples
- progressively routing endpoints from monolith to microservices
- replacing legacy billing with a new service behind a facade
