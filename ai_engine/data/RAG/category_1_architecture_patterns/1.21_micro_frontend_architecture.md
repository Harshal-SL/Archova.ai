# Micro-Frontend Architecture


## chunk_id
- 1.21

## category
- architecture_patterns

## type
- architecture

## definition
- An architecture where frontend is split into independent modules managed by different teams.

## when_to_use
- large frontend applications
- multiple frontend teams

## when_not_to_use
- small applications

## decision_signals
- need: large frontend applications
- need: multiple frontend teams
- willing to accept: integration complexity

## advantages
- independent deployments
- scalability

## disadvantages
- integration complexity

## anti_patterns
- using this when small applications
- ignoring the downside that integration complexity

## real_world_examples
- Spotify
- Amazon

## llm_hint
- Choose this pattern when workload behavior and failure modes justify the added architecture. Skip it when latency or simplicity is the primary constraint.
