# CRDT-Based Collaboration Architecture


## chunk_id
- 1.63

## category
- architecture_patterns

## type
- architecture

## definition
- an architecture for collaborative apps that uses conflict-free replicated data types to merge concurrent edits without central locking.

## when_to_use
- realtime collaboration with offline edits and intermittent connectivity
- multi-writer systems needing automatic conflict resolution
- applications requiring eventual convergence across replicas

## when_not_to_use
- domains needing strict global ordering or strong transactional constraints
- when simpler single-writer or server-authoritative models are sufficient

## decision_signals
- need: realtime collaboration with offline edits and intermittent connectivity
- need: multi-writer systems needing automatic conflict resolution
- willing to accept: data structures and semantics can be complex to design and test

## advantages
- enables offline-first collaboration with automatic merges
- reduces coordination overhead and avoids many write conflicts

## disadvantages
- data structures and semantics can be complex to design and test
- metadata overhead can increase storage and bandwidth

## anti_patterns
- using this when domains needing strict global ordering or strong transactional constraints
- use this when simpler single-writer or server-authoritative models are sufficient
- ignoring the downside that data structures and semantics can be complex to design and test

## real_world_examples
- collaborative document editing with concurrent cursors and edits
- distributed shared state for notes with offline sync
