# Multi-Tenant Architecture


## chunk_id
- 1.68

## category
- architecture_patterns

## type
- architecture

## definition
- an architecture where a single system instance serves multiple tenants while isolating data, security, and performance.

## when_to_use
- saas products serving many customers with shared infrastructure
- reducing cost by increasing resource utilization across tenants
- offering per-tenant configuration and limits

## when_not_to_use
- strict isolation requirements demanding dedicated infrastructure per tenant
- highly variable tenant workloads that cause noisy neighbor issues without controls

## decision_signals
- need: saas products serving many customers with shared infrastructure
- need: reducing cost by increasing resource utilization across tenants
- willing to accept: increased complexity for data isolation, quotas, and compliance

## advantages
- lowers cost per tenant via shared infrastructure
- simplifies operations by running fewer total deployments

## disadvantages
- increased complexity for data isolation, quotas, and compliance
- risk of noisy neighbors impacting performance and reliability

## anti_patterns
- using this when strict isolation requirements demanding dedicated infrastructure per tenant
- using this when highly variable tenant workloads that cause noisy neighbor issues without controls
- ignoring the downside that increased complexity for data isolation, quotas, and compliance

## real_world_examples
- b2b saas with tenant-scoped data and per-tenant rate limits
- shared database with tenant partitioning and row-level access controls
