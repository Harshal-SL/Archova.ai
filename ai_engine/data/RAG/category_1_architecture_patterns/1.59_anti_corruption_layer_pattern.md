# Anti-Corruption Layer Pattern


## chunk_id
- 1.59

## category
- architecture_patterns

## type
- pattern

## definition
- a ddd integration pattern that translates between a legacy or external model and an internal domain model to avoid leaking concepts.

## when_to_use
- integrating with legacy systems that have poor or incompatible models
- protecting a new bounded context during modernization
- consuming third-party apis with unstable or confusing semantics

## when_not_to_use
- simple integrations where direct mapping is trivial
- when teams cannot maintain translation logic and tests

## decision_signals
- need: integrating with legacy systems that have poor or incompatible models
- need: protecting a new bounded context during modernization
- willing to accept: adds mapping code and maintenance burden

## advantages
- protects domain integrity and reduces coupling to external models
- enables independent evolution of internal domain concepts

## disadvantages
- adds mapping code and maintenance burden
- can become a bottleneck if translation rules are complex

## anti_patterns
- using this when simple integrations where direct mapping is trivial
- use this when teams cannot maintain translation logic and tests
- ignoring the downside that adds mapping code and maintenance burden

## real_world_examples
- translating legacy customer codes to a new customer aggregate
- adapter layer mapping third-party payment events to internal commands
