# Competing Consumers Pattern


## chunk_id
- 1.49

## category
- architecture_patterns

## type
- pattern

## definition
- a messaging pattern where multiple consumer instances compete to process messages from the same queue for parallelism.

## when_to_use
- scaling message processing throughput horizontally
- background processing with independent tasks per message
- improving availability by running multiple worker instances

## when_not_to_use
- workloads requiring strict ordering across all messages
- tasks that must be processed by a specific consumer instance

## decision_signals
- need: scaling message processing throughput horizontally
- need: background processing with independent tasks per message
- willing to accept: requires idempotency and careful handling of duplicates

## advantages
- increases throughput and resilience via horizontal scaling
- naturally balances load across consumer instances

## disadvantages
- requires idempotency and careful handling of duplicates
- can create hotspots if message distribution is uneven

## anti_patterns
- using this when workloads requiring strict ordering across all messages
- using this when tasks that must be processed by a specific consumer instance
- ignoring the downside that requires idempotency and careful handling of duplicates

## real_world_examples
- worker pools consuming a shared job queue
- multiple instances consuming from a partitioned stream consumer group
