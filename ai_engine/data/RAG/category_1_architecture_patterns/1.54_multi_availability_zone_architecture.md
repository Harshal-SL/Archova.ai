# Multi-Availability Zone Architecture


## chunk_id
- 1.54

## category
- architecture_patterns

## type
- architecture

## definition
- an architecture that runs services across multiple availability zones within a region to tolerate zone-level failures.

## when_to_use
- production systems needing high availability without multi-region complexity
- services with state replication support across zones
- reducing blast radius for infrastructure and power failures

## when_not_to_use
- regions without multiple zones or services not zone-aware
- latency-sensitive workloads that cannot tolerate cross-zone hops

## decision_signals
- need: production systems needing high availability without multi-region complexity
- need: services with state replication support across zones
- willing to accept: increases networking costs and architecture complexity

## advantages
- improves availability for common infrastructure failure modes
- keeps data locality within a region for lower latency than multi-region

## disadvantages
- increases networking costs and architecture complexity
- requires careful placement, health checks, and failover testing

## anti_patterns
- using this when regions without multiple zones or services not zone-aware
- using this when latency-sensitive workloads that cannot tolerate cross-zone hops
- ignoring the downside that increases networking costs and architecture complexity

## real_world_examples
- web and api tiers deployed across three zones
- managed databases configured for multi-az replication
