# Timeout Pattern


## chunk_id
- 1.37

## category
- architecture_patterns

## type
- pattern

## definition
- a resilience pattern that bounds how long an operation can take before failing fast to protect system resources.

## when_to_use
- remote calls where tail latency can grow unbounded
- protecting thread pools and connection pools from saturation
- user-facing endpoints with strict latency slos

## when_not_to_use
- operations where partial completion must be awaited safely
- timeouts without cancellation and cleanup mechanisms

## decision_signals
- need: remote calls where tail latency can grow unbounded
- need: protecting thread pools and connection pools from saturation
- willing to accept: incorrect timeout values can increase error rates

## advantages
- prevents resource exhaustion and cascading failures
- improves predictability of latency and slos

## disadvantages
- incorrect timeout values can increase error rates
- requires careful handling of partial work and retries

## anti_patterns
- using this when operations where partial completion must be awaited safely
- using this when timeouts without cancellation and cleanup mechanisms
- ignoring the downside that incorrect timeout values can increase error rates

## real_world_examples
- http client timeouts on downstream api calls
- database query timeouts to prevent long locks
