# Write-Back Cache Pattern


## chunk_id
- 1.44

## category
- architecture_patterns

## type
- pattern

## definition
- a caching pattern where writes update the cache first and are persisted to the backing store asynchronously later.

## when_to_use
- high write workloads where write latency must be minimized
- systems tolerant of eventual persistence and recovery strategies
- aggregations like counters where buffering writes is beneficial

## when_not_to_use
- financial or compliance-critical data requiring durable writes
- systems without robust flush, retry, and crash recovery controls

## decision_signals
- need: high write workloads where write latency must be minimized
- need: systems tolerant of eventual persistence and recovery strategies
- willing to accept: risks data loss on cache failure without durable logging

## advantages
- reduces write latency and smooths write bursts
- can improve throughput by batching persistence

## disadvantages
- risks data loss on cache failure without durable logging
- increases complexity for consistency and recovery

## anti_patterns
- using this when financial or compliance-critical data requiring durable writes
- using this when systems without robust flush, retry, and crash recovery controls
- ignoring the downside that risks data loss on cache failure without durable logging

## real_world_examples
- buffered counter increments in redis with periodic flush
- write-behind caching for analytics rollups
