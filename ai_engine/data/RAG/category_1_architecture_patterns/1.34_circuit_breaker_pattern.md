# Circuit Breaker Pattern


## chunk_id
- 1.34

## category
- architecture_patterns

## type
- pattern

## definition
- a resilience pattern that stops calling a failing dependency to prevent cascading failures and allow recovery.

## when_to_use
- services calling slow or unreliable downstream dependencies
- high-qps systems where retries can amplify failure
- protecting shared resources like databases and third-party apis

## when_not_to_use
- pure in-process calls without remote failure modes
- when failures must always be propagated without fallback

## decision_signals
- need: services calling slow or unreliable downstream dependencies
- need: high-qps systems where retries can amplify failure
- willing to accept: requires tuning thresholds and fallback behavior

## advantages
- reduces cascading failures and protects system capacity
- improves recovery by giving dependencies time to heal

## disadvantages
- requires tuning thresholds and fallback behavior
- can mask underlying issues if misconfigured

## anti_patterns
- using this when pure in-process calls without remote failure modes
- use this when failures must always be propagated without fallback
- ignoring the downside that requires tuning thresholds and fallback behavior

## real_world_examples
- hystrix-style breakers in microservices
- envoy outlier detection and circuit breaking
