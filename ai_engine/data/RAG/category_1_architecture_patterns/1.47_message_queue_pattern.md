# Message Queue Pattern


## chunk_id
- 1.47

## category
- architecture_patterns

## type
- pattern

## definition
- a pattern that uses a queue to buffer work between producers and consumers for asynchronous processing.

## when_to_use
- smoothing bursts and decoupling request rate from processing rate
- background jobs like email sending and media processing
- isolating slow dependencies from user-facing requests

## when_not_to_use
- low-latency operations requiring immediate synchronous completion
- when losing or reordering messages is unacceptable without safeguards

## decision_signals
- need: smoothing bursts and decoupling request rate from processing rate
- need: background jobs like email sending and media processing
- willing to accept: introduces eventual consistency and operational overhead

## advantages
- improves resilience and absorbs traffic spikes
- enables load leveling and independent scaling of consumers

## disadvantages
- introduces eventual consistency and operational overhead
- requires idempotent handlers and robust retry semantics

## anti_patterns
- using this when low-latency operations requiring immediate synchronous completion
- use this when losing or reordering messages is unacceptable without safeguards
- ignoring the downside that introduces eventual consistency and operational overhead

## real_world_examples
- queueing image resize jobs for worker fleets
- asynchronous invoice generation after checkout
