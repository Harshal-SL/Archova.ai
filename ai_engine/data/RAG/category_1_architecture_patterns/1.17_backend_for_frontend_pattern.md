# Backend for Frontend Pattern


## chunk_id
- 1.17

## category
- architecture_patterns

## type
- pattern

## definition
- A pattern where separate backend services are created for different frontend clients.

## when_to_use
- multiple frontend clients
- mobile + web apps
- UI-specific optimizations

## when_not_to_use
- single frontend application

## decision_signals
- need: multiple frontend clients
- need: mobile + web apps
- willing to accept: increased maintenance

## advantages
- optimized APIs per client
- better performance
- flexibility

## disadvantages
- increased maintenance
- duplication of logic

## anti_patterns
- using this when single frontend application
- ignoring the downside that increased maintenance

## real_world_examples
- Netflix frontend architecture
