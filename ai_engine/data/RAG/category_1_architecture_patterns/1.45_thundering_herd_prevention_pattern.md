# Thundering Herd Prevention Pattern


## chunk_id
- 1.45

## category
- architecture_patterns

## type
- pattern

## definition
- a pattern that prevents many clients from simultaneously triggering expensive recomputation or cache misses.

## when_to_use
- cache-aside workloads with synchronized ttl expirations
- high-qps endpoints rebuilding shared hot objects
- cold start events and traffic spikes after outages

## when_not_to_use
- low traffic systems without synchronized bursts
- when added coordination overhead exceeds the risk

## decision_signals
- need: cache-aside workloads with synchronized ttl expirations
- need: high-qps endpoints rebuilding shared hot objects
- willing to accept: requires coordination mechanisms like locks or request coalescing

## advantages
- reduces stampede load on databases and downstream services
- improves tail latency during cache rebuilds

## disadvantages
- requires coordination mechanisms like locks or request coalescing
- misconfiguration can reduce cache effectiveness

## anti_patterns
- using this when low traffic systems without synchronized bursts
- use this when added coordination overhead exceeds the risk
- ignoring the downside that requires coordination mechanisms like locks or request coalescing

## real_world_examples
- singleflight request coalescing for cache misses
- jittered ttl and soft expiration with background refresh
