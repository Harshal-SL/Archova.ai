# Event Sourcing Pattern


## chunk_id
- 1.12

## category
- architecture_patterns

## type
- pattern

## definition
- A pattern where all changes to application state are stored as a sequence of events.

## when_to_use
- systems requiring audit logs
- event-driven systems
- financial systems

## when_not_to_use
- simple applications
- systems without event tracking needs

## decision_signals
- need: systems requiring audit logs
- need: event-driven systems
- willing to accept: complex implementation

## advantages
- complete audit history
- easy debugging
- replay capability

## disadvantages
- complex implementation
- storage overhead

## anti_patterns
- using this when simple applications
- using this when systems without event tracking needs
- ignoring the downside that complex implementation

## real_world_examples
- banking systems
- trading platforms
