# Service Discovery Pattern


## chunk_id
- 1.32

## category
- architecture_patterns

## type
- pattern

## definition
- a conceptual pattern for dynamic endpoint resolution where service instances are discovered at runtime instead of hard-coded addresses.

## when_to_use
- microservices with frequent scaling and dynamic instance lifecycles
- multi-region or multi-az service deployments
- systems needing client-side or sidecar-based load balancing

## when_not_to_use
- single-instance systems with static endpoints
- simple deployments where dns or config is sufficient

## decision_signals
- need: microservices with frequent scaling and dynamic instance lifecycles
- need: multi-region or multi-az service deployments
- willing to accept: adds control plane dependency and operational overhead

## advantages
- enables dynamic scaling without manual reconfiguration
- improves resilience by routing around unhealthy instances

## disadvantages
- adds control plane dependency and operational overhead
- requires consistent health checks and registration semantics

## anti_patterns
- using this for single-instance systems with static endpoints
- using this for simple deployments where dns or config is sufficient
- ignoring the downside that it adds control plane dependency and operational overhead

## real_world_examples
- clients resolving service instances via dynamic registries and health models
- platform-level endpoint resolution enabling elastic service topologies
