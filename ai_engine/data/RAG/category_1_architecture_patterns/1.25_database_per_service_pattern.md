# Database per Service Pattern


## chunk_id
- 1.25

## category
- architecture_patterns

## type
- pattern

## definition
- A pattern where each service has its own dedicated database.

## when_to_use
- microservices architecture
- independent service ownership

## when_not_to_use
- monolithic systems

## decision_signals
- need: microservices architecture
- need: independent service ownership
- willing to accept: data consistency issues

## advantages
- data isolation
- independent scaling

## disadvantages
- data consistency issues
- complex queries

## anti_patterns
- using this when monolithic systems
- ignoring the downside that data consistency issues

## real_world_examples
- Netflix microservices

## llm_hint
- This fits systems that need strong guardrails for growth, resiliency, or isolation. Prefer leaner designs when those pressures are low.
