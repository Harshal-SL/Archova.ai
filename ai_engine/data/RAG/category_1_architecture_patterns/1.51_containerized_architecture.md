# Containerized Architecture


## chunk_id
- 1.51

## category
- architecture_patterns

## type
- architecture

## definition
- an architecture style that packages applications and dependencies into containers for consistent deployment across environments.

## when_to_use
- standardizing runtime environments across dev, ci, and production
- deploying multiple services with consistent build and release pipelines
- isolating dependencies and reducing host-level configuration drift

## when_not_to_use
- very small apps where vm or managed runtime is simpler
- strict security environments without a container hardening program

## decision_signals
- need: standardizing runtime environments across dev, ci, and production
- need: deploying multiple services with consistent build and release pipelines
- willing to accept: adds image build, registry, and vulnerability management overhead

## advantages
- improves portability and repeatability of deployments
- enables faster scaling and better resource density than full vms

## disadvantages
- adds image build, registry, and vulnerability management overhead
- requires careful networking, storage, and observability integration

## anti_patterns
- using this when very small apps where vm or managed runtime is simpler
- using this when strict security environments without a container hardening program
- ignoring the downside that adds image build, registry, and vulnerability management overhead

## real_world_examples
- microservices deployed as docker containers on a cluster
- batch workers packaged as container images for scheduled runs
