# CQRS Pattern


## chunk_id
- 1.11

## category
- architecture_patterns

## type
- pattern

## definition
- A pattern that separates read (query) and write (command) operations into different models or services.

## when_to_use
- high read vs write imbalance
- complex business logic systems
- systems requiring optimized queries

## when_not_to_use
- simple CRUD applications
- low traffic systems

## decision_signals
- need: high read vs write imbalance
- need: complex business logic systems
- willing to accept: increased complexity

## advantages
- optimized read and write performance
- scalability
- flexibility in data models

## disadvantages
- increased complexity
- data consistency challenges

## anti_patterns
- using this when simple CRUD applications
- using this when low traffic systems
- ignoring the downside that increased complexity

## real_world_examples
- banking systems
- e-commerce platforms
