# Bulkhead Pattern


## chunk_id
- 1.35

## category
- architecture_patterns

## type
- pattern

## definition
- a resilience pattern that isolates resources into separate pools to prevent one workload from exhausting shared capacity.

## when_to_use
- multi-tenant services with noisy neighbor risk
- services with mixed latency classes and priority tiers
- limiting database connections per endpoint or per client

## when_not_to_use
- low-traffic systems where one pool is sufficient
- when resource partitioning reduces overall utilization too much

## decision_signals
- need: multi-tenant services with noisy neighbor risk
- need: services with mixed latency classes and priority tiers
- willing to accept: requires careful sizing and monitoring of each pool

## advantages
- contains failures and preserves capacity for critical paths
- improves predictability by limiting contention

## disadvantages
- requires careful sizing and monitoring of each pool
- can waste capacity if partitions are underutilized

## anti_patterns
- using this when low-traffic systems where one pool is sufficient
- use this when resource partitioning reduces overall utilization too much
- ignoring the downside that requires careful sizing and monitoring of each pool

## real_world_examples
- separate thread pools for reads and writes in api services
- per-tenant rate and connection pools in gateways
