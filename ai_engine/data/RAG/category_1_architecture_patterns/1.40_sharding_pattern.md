# Sharding Pattern


## chunk_id
- 1.40

## category
- architecture_patterns

## type
- pattern

## definition
- a data scaling pattern that partitions a dataset across multiple nodes using a shard key for parallel storage and throughput.

## when_to_use
- datasets exceeding single-node storage or write capacity
- multi-tenant workloads with high throughput requirements
- latency needs that require localized partitions

## when_not_to_use
- when indexing, caching, and read replicas are sufficient
- when cross-shard transactions and joins are frequent

## decision_signals
- need: datasets exceeding single-node storage or write capacity
- need: multi-tenant workloads with high throughput requirements
- willing to accept: increases operational complexity and resharding effort

## advantages
- scales writes and storage horizontally
- reduces per-node load by partitioning traffic

## disadvantages
- increases operational complexity and resharding effort
- complicates queries, aggregation, and consistency

## anti_patterns
- use this when indexing, caching, and read replicas are sufficient
- use this when cross-shard transactions and joins are frequent
- ignoring the downside that increases operational complexity and resharding effort

## real_world_examples
- sharded user collections in large multi-tenant systems
- partitioned time-series ingestion across shards
