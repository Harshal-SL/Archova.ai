# Read-Replica Pattern


## chunk_id
- 1.41

## category
- architecture_patterns

## type
- pattern

## definition
- a database scaling pattern that serves read traffic from replicated followers while a primary handles writes.

## when_to_use
- read-heavy workloads needing higher read throughput
- isolating analytics or reporting reads from write traffic
- reducing latency by placing replicas near users

## when_not_to_use
- write-heavy workloads where replication lag breaks correctness
- read paths requiring strict read-your-writes semantics

## decision_signals
- need: read-heavy workloads needing higher read throughput
- need: isolating analytics or reporting reads from write traffic
- willing to accept: introduces replication lag and stale reads

## advantages
- increases read capacity without changing write model
- reduces load on the primary and improves availability

## disadvantages
- introduces replication lag and stale reads
- adds operational complexity and failover considerations

## anti_patterns
- using this when write-heavy workloads where replication lag breaks correctness
- using this when read paths requiring strict read-your-writes semantics
- ignoring the downside that introduces replication lag and stale reads

## real_world_examples
- product catalog served from geo-read replicas
- reporting queries routed to read replicas
