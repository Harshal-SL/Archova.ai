# Edge Computing Architecture


## chunk_id
- 1.55

## category
- architecture_patterns

## type
- architecture

## definition
- an architecture that runs compute closer to users or devices to reduce latency and bandwidth to centralized regions.

## when_to_use
- ultra-low latency interactions and realtime control loops
- reducing bandwidth costs by pre-processing data near the source
- improving availability for intermittently connected devices

## when_not_to_use
- workloads needing centralized data and strict consistency
- teams that cannot manage distributed deployment and observability

## decision_signals
- need: ultra-low latency interactions and realtime control loops
- need: reducing bandwidth costs by pre-processing data near the source
- willing to accept: increases operational complexity across many locations

## advantages
- reduces latency and improves responsiveness
- lowers backhaul bandwidth by filtering and aggregating at the edge

## disadvantages
- increases operational complexity across many locations
- harder security and patch management across distributed nodes

## anti_patterns
- using this when workloads needing centralized data and strict consistency
- using this when teams that cannot manage distributed deployment and observability
- ignoring the downside that increases operational complexity across many locations

## real_world_examples
- iot gateways performing local inference before cloud upload
- edge functions for personalization and request routing
