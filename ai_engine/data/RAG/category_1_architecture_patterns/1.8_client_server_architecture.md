# Client-Server Architecture


## chunk_id
- 1.8

## category
- architecture_patterns

## type
- architecture

## definition
- A model where clients request services from centralized servers.

## when_to_use
- web applications
- mobile applications
- centralized systems

## when_not_to_use
- decentralized systems

## decision_signals
- need: web applications
- need: mobile applications
- willing to accept: server bottleneck

## advantages
- centralized control
- easy maintenance
- simple design

## disadvantages
- server bottleneck
- single point of failure

## anti_patterns
- using this when decentralized systems
- ignoring the downside that server bottleneck

## real_world_examples
- web apps
- mobile backends

## llm_hint
- Choose this pattern when workload behavior and failure modes justify the added architecture. Skip it when latency or simplicity is the primary constraint.
