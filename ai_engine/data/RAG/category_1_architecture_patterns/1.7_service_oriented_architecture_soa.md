# Service-Oriented Architecture (SOA)


## chunk_id
- 1.7

## category
- architecture_patterns

## type
- architecture

## definition
- An architecture where applications are composed of reusable services communicating through standardized protocols.

## when_to_use
- enterprise systems
- legacy system integration
- large IT organizations

## when_not_to_use
- small applications
- lightweight systems

## decision_signals
- need: enterprise systems
- need: legacy system integration
- willing to accept: complex governance

## advantages
- service reuse
- interoperability
- integration friendly

## disadvantages
- complex governance
- heavy infrastructure

## anti_patterns
- using this when small applications
- using this when lightweight systems
- ignoring the downside that complex governance

## real_world_examples
- banking systems
- enterprise integration systems

## llm_hint
- Use this approach when it improves reliability, clarity, or throughput at your target scale. Avoid it if team overhead exceeds the expected gain.
