# Data Lake Architecture


## chunk_id
- 1.29

## category
- architecture_patterns

## type
- architecture

## definition
- an architecture that stores large volumes of raw and semi-structured data in centralized, low-cost storage for analytics.

## when_to_use
- analytics and ml workloads needing raw historical data
- ingesting diverse sources with evolving schemas
- long-term retention and backfills for data pipelines

## when_not_to_use
- oltp transactional workloads needing low-latency queries
- teams without governance to prevent a data swamp

## decision_signals
- need: analytics and ml workloads needing raw historical data
- need: ingesting diverse sources with evolving schemas
- willing to accept: requires governance, cataloging, and quality controls

## advantages
- supports flexible schema-on-read and broad data ingestion
- enables cost-effective storage of large datasets

## disadvantages
- requires governance, cataloging, and quality controls
- can lead to inconsistent datasets and duplicated pipelines

## anti_patterns
- using this when oltp transactional workloads needing low-latency queries
- using this when teams without governance to prevent a data swamp
- ignoring the downside that requires governance, cataloging, and quality controls

## real_world_examples
- s3-based lakes feeding spark and presto queries
- hadoop lakes powering enterprise analytics
