# Lambda Architecture


## chunk_id
- 1.30

## category
- architecture_patterns

## type
- architecture

## definition
- an architecture combining batch and stream processing paths to provide accurate and low-latency views over data.

## when_to_use
- systems needing realtime views plus accurate recomputation
- high-volume event ingestion with backfills and reprocessing
- analytics pipelines requiring both speed and correctness

## when_not_to_use
- simple pipelines where one processing mode is sufficient
- teams that cannot operate two parallel processing stacks

## decision_signals
- need: systems needing realtime views plus accurate recomputation
- need: high-volume event ingestion with backfills and reprocessing
- willing to accept: duplicates logic across batch and speed layers

## advantages
- provides low-latency results with batch-corrected accuracy
- supports replay and recomputation for correctness

## disadvantages
- duplicates logic across batch and speed layers
- increases operational and maintenance complexity

## anti_patterns
- using this when simple pipelines where one processing mode is sufficient
- using this when teams that cannot operate two parallel processing stacks
- ignoring the downside that duplicates logic across batch and speed layers

## real_world_examples
- realtime analytics with kafka streams plus nightly spark jobs
- fraud detection with streaming signals and batch reconciliation
