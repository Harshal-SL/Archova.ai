# Rate Limiter Pattern


## chunk_id
- 1.38

## category
- architecture_patterns

## type
- pattern

## definition
- a pattern that limits request or event rates to protect services from overload and enforce fairness.

## when_to_use
- public apis vulnerable to abuse or traffic spikes
- protecting shared dependencies like databases and third-party apis
- multi-tenant systems needing per-tenant quotas

## when_not_to_use
- internal trusted traffic where limiting would break critical flows
- without clear policies for bursts and backoff behavior

## decision_signals
- need: public apis vulnerable to abuse or traffic spikes
- need: protecting shared dependencies like databases and third-party apis
- willing to accept: can reject legitimate bursts without proper burst handling

## advantages
- prevents overload and improves system stability
- enables fair usage and predictable capacity planning

## disadvantages
- can reject legitimate bursts without proper burst handling
- requires distributed coordination for global limits

## anti_patterns
- using this when internal trusted traffic where limiting would break critical flows
- using this when without clear policies for bursts and backoff behavior
- ignoring the downside that can reject legitimate bursts without proper burst handling

## real_world_examples
- token bucket limits at an api gateway
- per-user login attempt throttling
