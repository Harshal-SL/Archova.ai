# Plugin-Based Architecture


## chunk_id
- 1.69

## category
- architecture_patterns

## type
- architecture

## definition
- an architecture that extends a core application through plugins loaded via stable extension points and contracts.

## when_to_use
- product ecosystems needing third-party or team-owned extensions
- separating core platform from optional capabilities
- enabling customization without forking the core codebase

## when_not_to_use
- small codebases where modularization is enough
- when extension points cannot be made stable and secure

## decision_signals
- need: product ecosystems needing third-party or team-owned extensions
- need: separating core platform from optional capabilities
- willing to accept: requires strong versioning, sandboxing, and compatibility management

## advantages
- improves extensibility and supports independent feature delivery
- reduces core complexity by moving optional features to plugins

## disadvantages
- requires strong versioning, sandboxing, and compatibility management
- increases security risk if plugins can execute untrusted code

## anti_patterns
- using this when small codebases where modularization is enough
- use this when extension points cannot be made stable and secure
- ignoring the downside that requires strong versioning, sandboxing, and compatibility management

## real_world_examples
- IDEs with language and tool plugins
- e-commerce platforms with payment and shipping plugins
