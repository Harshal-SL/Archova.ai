# Polyglot Persistence Pattern


## chunk_id
- 1.27

## category
- architecture_patterns

## type
- pattern

## definition
- a pattern where different data stores are used for different workloads within the same system.

## when_to_use
- distinct access patterns like search, graph, and transactions
- performance needs that one database cannot meet
- domain boundaries that benefit from specialized storage

## when_not_to_use
- small systems where one database meets all needs
- teams lacking operational maturity for multiple datastores

## decision_signals
- need: distinct access patterns like search, graph, and transactions
- need: performance needs that one database cannot meet
- willing to accept: increases operational complexity and monitoring burden

## advantages
- optimizes each workload with the best-fit database
- improves performance and scalability for diverse data models

## disadvantages
- increases operational complexity and monitoring burden
- complicates consistency and cross-store queries

## anti_patterns
- using this when small systems where one database meets all needs
- using this when teams lacking operational maturity for multiple datastores
- ignoring the downside that increases operational complexity and monitoring burden

## real_world_examples
- PostgreSQL for transactions and Elasticsearch for search
- Redis for caching and MongoDB for document storage
