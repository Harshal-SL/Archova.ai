# Geospatial Data Modeling


## chunk_id
- 5.22

## category
- database_design

## type
- data_pattern

## definition
- storing and indexing locations and shapes to support distance, containment, and proximity queries.

## when_to_use
- nearby search (stores, drivers, deliveries)
- geofencing and region-based routing
- spatial analytics over coordinates and polygons

## when_not_to_use
- when location is used only for display and never queried
- when coordinate quality is poor and would yield unreliable results

## decision_signals
- need: nearby search (stores, drivers, deliveries)
- need: geofencing and region-based routing
- willing to accept: spatial indexes have tradeoffs and can be expensive to maintain

## advantages
- enables efficient spatial queries with proper indexes
- supports location-aware features and routing

## disadvantages
- spatial indexes have tradeoffs and can be expensive to maintain
- edge cases (dateline, projection, precision) can cause subtle bugs

## anti_patterns
- use this when location is used only for display and never queried
- use this when coordinate quality is poor and would yield unreliable results
- ignoring the downside that spatial indexes have tradeoffs and can be expensive to maintain

## real_world_examples
- querying drivers within 2 km of a pickup point
- assigning deliveries to service zones defined by polygons
