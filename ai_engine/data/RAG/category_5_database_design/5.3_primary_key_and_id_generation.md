# Primary Key and ID Generation


## chunk_id
- 5.3

## category
- database_design

## type
- data_pattern

## definition
- selecting stable identifiers and generation strategies (uuid, ulid, sequences) that support indexing, sharding, and ordering needs.

## when_to_use
- designing new tables or collections
- planning sharding or multi-region writes
- preventing hot partitions caused by monotonically increasing ids

## when_not_to_use
- when ids are purely internal and never exposed, and the current scheme is working
- when changing ids would break contracts without a migration plan

## decision_signals
- need: designing new tables or collections
- need: planning sharding or multi-region writes
- willing to accept: poor choices can create write hotspots or large indexes

## advantages
- improves index locality and query performance when aligned with access patterns
- reduces collisions and supports safe replication and merging

## disadvantages
- poor choices can create write hotspots or large indexes
- changing id formats later can be disruptive

## anti_patterns
- use this when ids are purely internal and never exposed, and the current scheme is working
- use this when changing ids would break contracts without a migration plan
- ignoring the downside that poor choices can create write hotspots or large indexes

## real_world_examples
- using ulids to preserve time ordering while avoiding single-leader sequence contention
- using composite keys (tenant_id, entity_id) to enforce isolation
