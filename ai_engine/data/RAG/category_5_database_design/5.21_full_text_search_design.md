# Full-Text Search Design


## chunk_id
- 5.21

## category
- database_design

## type
- data_pattern

## definition
- designing searchable fields, analyzers, and indexing pipelines to support relevance-based queries over text.

## when_to_use
- user-facing search over names, descriptions, or documents
- filtering and ranking results with relevance scoring
- implementing autocomplete, stemming, or fuzziness

## when_not_to_use
- when exact key lookups are sufficient
- when search requirements exceed the database capabilities and need a dedicated search engine

## decision_signals
- need: user-facing search over names, descriptions, or documents
- need: filtering and ranking results with relevance scoring
- willing to accept: indexing pipelines can be complex and resource intensive

## advantages
- improves user experience with fast, relevant search
- enables flexible discovery beyond structured filters

## disadvantages
- indexing pipelines can be complex and resource intensive
- relevance tuning and evaluation require ongoing iteration

## anti_patterns
- use this when exact key lookups are sufficient
- use this when search requirements exceed the database capabilities and need a dedicated search engine
- ignoring the downside that indexing pipelines can be complex and resource intensive

## real_world_examples
- indexing product titles and descriptions with language-aware analyzers
- building a search index projection from catalog change events
