# Time-Series Data Modeling


## chunk_id
- 5.11

## category
- database_design

## type
- data_pattern

## definition
- structuring time-stamped measurements for efficient ingestion, rollups, and range queries.

## when_to_use
- high-volume telemetry, metrics, and iot ingestion
- dashboards that query recent windows and aggregates
- retention policies that downsample older data

## when_not_to_use
- when data is sparse and queried mostly by entity, not time ranges
- when strict per-record updates are required (time-series favors append)

## decision_signals
- need: high-volume telemetry, metrics, and iot ingestion
- need: dashboards that query recent windows and aggregates
- willing to accept: can be expensive if cardinality is unbounded (too many series)

## advantages
- fast range queries and predictable storage patterns
- supports tiered retention and rollups

## disadvantages
- can be expensive if cardinality is unbounded (too many series)
- rollups and downsampling add pipeline complexity

## anti_patterns
- use this when data is sparse and queried mostly by entity, not time ranges
- use this when strict per-record updates are required (time-series favors append)
- ignoring the downside that can be expensive if cardinality is unbounded (too many series)

## real_world_examples
- storing service latency metrics keyed by (service, region) with minute buckets
- writing device readings and aggregating hourly summaries
