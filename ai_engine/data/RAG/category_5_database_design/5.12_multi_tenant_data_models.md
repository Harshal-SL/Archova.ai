# Multi-Tenant Data Models


## chunk_id
- 5.12

## category
- database_design

## type
- data_pattern

## definition
- modeling data so multiple tenants share infrastructure while maintaining isolation, fairness, and clear ownership.

## when_to_use
- saas platforms serving many customer organizations
- enforcing per-tenant access and billing boundaries
- planning tenant-level retention, backups, and export

## when_not_to_use
- when tenants require dedicated infrastructure for compliance
- when per-tenant customization would fragment the schema beyond maintainability

## decision_signals
- need: saas platforms serving many customer organizations
- need: enforcing per-tenant access and billing boundaries
- willing to accept: isolation mistakes can cause cross-tenant data leaks

## advantages
- improves cost efficiency through shared resources
- enables consistent governance and operational tooling

## disadvantages
- isolation mistakes can cause cross-tenant data leaks
- noisy neighbors can create performance variability without controls

## anti_patterns
- use this when tenants require dedicated infrastructure for compliance
- use this when per-tenant customization would fragment the schema beyond maintainability
- ignoring the downside that isolation mistakes can cause cross-tenant data leaks

## real_world_examples
- including tenant_id in every primary key and index prefix
- separating large tenants into dedicated partitions while sharing the schema
