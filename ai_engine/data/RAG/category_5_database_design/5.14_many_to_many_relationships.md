# Many-to-Many Relationships


## chunk_id
- 5.14

## category
- database_design

## type
- data_pattern

## definition
- representing relationships where many records relate to many others using join tables, link collections, or adjacency models.

## when_to_use
- users can belong to many groups and groups contain many users
- tagging systems where items have many tags and tags map to many items
- permissions and roles with complex mappings

## when_not_to_use
- when a relationship is actually one-to-many and can be modeled simply
- when unbounded arrays would exceed document or row size limits

## decision_signals
- need: users can belong to many groups and groups contain many users
- need: tagging systems where items have many tags and tags map to many items
- willing to accept: requires careful indexing for both directions

## advantages
- supports flexible queries and avoids duplication of relationship state
- can enforce uniqueness constraints on links

## disadvantages
- requires careful indexing for both directions
- can create heavy join/link lookups under high fan-out

## anti_patterns
- use this when a relationship is actually one-to-many and can be modeled simply
- use this when unbounded arrays would exceed document or row size limits
- ignoring the downside that requires careful indexing for both directions

## real_world_examples
- a user_group_membership table with indexes on (user_id) and (group_id)
- a tag_item link collection with a compound key (tag_id, item_id)
