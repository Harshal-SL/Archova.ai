# Zoom Video Conferencing System

## chunk_id
- 10.8


## category
- real_world_systems

## type
- real_world_system

## definition
- a real-time video conferencing system optimized for low latency media transport, reliability under variable networks, and large meetings.

## when_to_use
- designing real-time media with jitter, packet loss, and adaptive bitrate
- supporting meeting state, chat, recording, and moderation features
- optimizing global routing to minimize latency and improve quality

## when_not_to_use
- asynchronous video hosting where latency is not real-time
- small meetings where managed services handle all media concerns

## decision_signals
- end-to-end media latency target (<250ms) for interactive voice/video
- variable client networks require congestion control and adaptation
- large rooms (100+ participants) need scalable fan-out and mixing strategies

## advantages
- focuses architecture on latency budgets and network resilience
- supports degraded modes (audio-only) during network issues

## disadvantages
- media infrastructure is costly and complex to operate globally
- quality issues can be hard to debug without strong telemetry

## anti_patterns
- sending full mesh streams for large meetings without scaling plan
- ignoring packet loss and relying on retries instead of adaptation
- coupling meeting control plane to media plane availability

## real_world_examples
- selective forwarding units (sfu) routing streams to participants
- regional edge routing with adaptive bitrate and codec negotiation
