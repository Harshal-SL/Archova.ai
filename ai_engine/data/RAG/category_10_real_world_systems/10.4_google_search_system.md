# Google Search System

## chunk_id
- 10.4


## category
- real_world_systems

## type
- real_world_system

## definition
- a web search system that crawls and indexes the web and serves low-latency ranked results with large-scale distributed storage.

## when_to_use
- designing indexing pipelines and query-time ranking under tight latency
- modeling separation of crawling, indexing, and serving layers
- building highly available read-heavy query systems

## when_not_to_use
- small domain-specific search where a managed search engine suffices
- systems without a need for ranking, crawling, and massive indexing

## decision_signals
- query latency budget (<200ms p95) with global traffic
- index size and update rate require distributed ingestion and compaction
- ranking requires offline evaluation plus online serving

## advantages
- strong decoupling between offline indexing and online serving
- scalable partitioning and replication for read-heavy traffic

## disadvantages
- high operational complexity for indexing freshness and ranking quality
- heavy compute and storage requirements for crawl/index workloads

## anti_patterns
- rebuilding indexes without incremental pipelines and backfill plans
- coupling query serving to synchronous index updates
- ignoring tail latency and cache strategy for common queries

## real_world_examples
- inverted index with shard replication and query fan-out
- offline ranking experiments feeding online models and signals
